# 渐进式加载与知识地图

> 目标不是把内容分散到更多文件，而是让每次读取都缩小当前问题的搜索空间。

## 两级路由与两条导航轴

渐进式加载先发生在 Skill 之间，再发生在 Skill 内部：

```text
用户意图
→ 根据 name + description 选择相关 Skill
→ 读取该 Skill 的 SKILL.md 地图
→ 根据当前 Repo / WorkTree / Feature / Run 选择局部索引
→ 读取少量相关 reference 或 Memory
```

第一层避免加载无关能力，第二层避免加载一个 Skill 已积累的全部知识。Workflow 不需要维护一份固定 Skill 清单；经验包也不需要把所有内容写进主文件。

### 能力轴

```text
用户意图
→ skills-map / 总 Skill
→ 当前阶段 Skill
→ 本阶段必要的 reference、schema 或脚本
```

总 Skill 只保留：触发边界、全局不变量、阶段顺序、横切规则和下一跳。阶段实现、工具配方和示例留在子 Skill 或 reference。

### 记忆轴

```text
当前任务
→ root index
→ 当前 Feature/WorkTree map 或 1 张最相关主题 map（跨域最多 2 张）
→ 1–3 条原子 memory
→ 本次可执行的防错动作
```

记忆按“我正在做什么”导航，而不是按标签或技术名词导航。标签只辅助搜索。

## 索引的语义责任

有效入口至少说明：

- 这一层解决什么问题；
- 什么情况下值得进入；
- 进入前应建立什么心智模型；
- 下一步建议读什么，以及为什么。

只有文件名、数量或标签的目录不是知识地图。

根索引也不能退化为全部 Memory 的平铺清单。它只列稳定的问题域、当前活跃 Feature 入口和必要的查找提示；具体条目留在下一层 map。这样即使本地 Memory 达到数 GB，Agent 开局仍只读取一个很短的入口。

本地索引与本地 Memory 一同变化，默认位于被 Git 忽略的 `local/` 中。仓库提交的是读取协议和可分享 reference，不提交本机 Feature 名、运行历史、私有路径或全量索引。

## 按真实规模生长

- **没有内容**：不建空目录、空地图或占位 memory。
- **1–2 条零散错误**：可直接挂在根 index 的“尚未成簇”区域。
- **至少 3 条共享同一问题模型**：提炼主题地图，而不是机械分类。
- **根地图出现约 7 个以上稳定入口**：合并相近任务意图，必要时增加一层领域 index。
- **同一 Repo 出现多个并行 WorkTree/Feature**：为每个 Feature 建独立入口，优先按显式任务 ID、WorkTree 名、分支名、Repo ID 的顺序定位。
- **阶段 Skill 出现大量互斥变体**：把变体细节放进一层 reference；主流程仍只保留选择规则。

数字是提醒，不是自动拆分器。是否拆分最终取决于：读取下一层能否明显减少不确定性。

## 读取纪律

1. 开局只读总地图和 memory 根 index，确定本轮路径。
2. 先解析当前 Repo、WorkTree、Feature 或 Run 标识；命中专属 map 时优先读取它，再考虑通用主题地图。
3. 到真实需要某项能力时才加载对应 Skill、reference 和 Memory，不按固定阶段预读。
4. 已经转成防错动作的 memory 不重复读取，除非当前证据与它冲突。
5. 当前证据优先于历史记忆；冲突时复核并更新旧记忆状态。
6. 日常运行不加载迁移模板、历史评审台账、其他 Feature 或 archive。

## 写入纪律

- 新内容先查重，再决定更新原文还是创建新条目；
- 添加 memory 后检查从根 index 是否可达；
- 大量原始资料可以保留在当前 Run 中，但根索引只登记一条摘要或对应 Feature map，不逐文件暴露；
- 索引由人或 AI 做语义策展，lint 只查断链、重复 ID 和孤立项；
- 不从 frontmatter 自动生成主地图，因为 metadata 不能替代“为什么进入”的判断。

## 反模式

- 主 Skill 和子 Skill 重复同一套细节；
- 开工一次性读取所有子 Skill；
- 根 index 已经完整读 memory，阶段入口又从头重复读取；
- reference 多层套娃，入口不知道何时加载；
- 为了结构整齐提前生成空分类；
- 单文件无限追加，再用搜索命令假装实现了渐进加载。
- 把全部 Memory 文件名塞进根索引，制造另一种大文件；
- 同一上下文里先把结果写成 Markdown，再让下一个 Skill 原样读回。
