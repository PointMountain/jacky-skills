# 任务复盘、错误记忆与两轮评分

> 评分发现当前产物的问题，复盘汇总本轮运行的事实，memory 保存会影响未来决策的已验证根因。三者前后衔接，但不能直接画等号。

## 每个阶段交接都评分

复杂工作流在每个生产阶段结束后，由与生成者隔离的独立 AI 评审：

1. 读取本阶段 rubric、产物和参考证据；
2. 先执行 `must_pass` 事实校验；
3. 对主观质量维度逐项打分并给证据；
4. 只选一个对结果影响最大、当前可修的 `top_fix`；
5. 未达阈值时由原阶段只修这一项，再做第二轮独立复评；
6. 第二轮后停止评审循环，不要求主观意见收敛。

评审的目标是以有限成本提高质量，不是拿满分。

## `must_pass` 与主观评分分开

`must_pass` 是可证伪事实，例如产物能否打开、测试是否通过、链接是否可访问。它不参与加权平均，也不能因两轮用完而变成“成功”。

主观维度用于比较质量，例如视觉层级、表达清晰度或动效节奏。第二轮仍低于阈值时可以继续流程，但必须保留 residual，不能伪装成已达标。

## 低分只产生候选

```text
低分 / 失败 / 用户纠正
→ memory_candidate
→ 真实错误？
→ 根因已验证？
→ 未来可能复现？
→ 三项全是：查重后写 memory
→ 任一不是：留在本轮 residual/backlog
```

审美偏好、一次性未完成和未经验证的猜测不能进入错误记忆。

## 任务结束复盘是沉淀闸门

任务进入 `success`、`partial` 或 `failed` 终止态后，用本轮已有工件做一次复盘。复盘不重新生成产物，也不增加第三轮评分；它只整理可审计事实，并把可能影响未来决策的内容送入候选区。

事实来源包括：

- 最终产物及其验收结果；
- `must_pass`、测试、命令输出、日志和可复核链接；
- 各阶段评分、`top_fix` 与未解决的 residual；
- 用户明确的确认、纠正或拒绝；
- 本轮 Skills 使用清单中的选择、降级、结果与摩擦。

最小复盘工件可以写成：

```yaml
retrospective:
  run_id: "<run-id>"
  objective: "<本轮目标>"
  result: success # success | partial | failed
  skills_manifest_ref: "<skill_usage_manifest 路径或工件 ID>"
  evidence:
    - ref: "<产物、测试、日志或用户确认>"
      proves: "<这份证据证明了什么>"
  findings:
    - type: effective_pattern # effective_pattern | failure_root_cause | environment_fact | skill_friction
      claim: "<可验证陈述>"
      evidence_refs: ["<evidence-ref>"]
      applies_to: ["<场景或阶段>"]
      destination_candidate: reference # local_memory | error_memory | reference | skill_adjustment | backlog
      status: candidate
```

复盘只记录“发生了什么、证据是什么、适用边界在哪里”，不保存冗长原始推理。没有 `evidence_refs` 的 finding 只能留在 backlog，不能进入长期层。

## 经验如何从候选晋升

“经验沉淀”不是把复盘全文存起来，而是对候选逐条验证、查重和分流：

| 候选类型 | 晋升条件 | 归宿 |
|---|---|---|
| 已验证错误根因 | 真实错误、根因已验证、未来可能复现 | 原子错误 memory |
| 通用有效模式 | 有直接证据，且跨任务仍成立或已重复验证 | 对应 Skill 或 reference |
| 环境专属事实 | 当前环境已验证，且标明核实时间与边界 | gitignored 本地 memory |
| Skill 能力摩擦 | 能定位到能力槽位，并有重复证据或明确的契约缺口 | `skill_adjustment_candidate` |
| 猜测或一次性现象 | 证据不足、不可复现或没有未来价值 | residual / backlog |

每个晋升项都必须满足：

1. **事实可证伪**：写成可被当前或未来证据推翻的陈述，而不是感受。
2. **证据可定位**：能回到产物、测试、日志、评分或用户确认。
3. **适用边界明确**：说明对哪个 Skill、阶段、环境或输入成立。
4. **已查重与查冲突**：同一根因更新原条目；新事实与旧经验冲突时更新旧状态。
5. **归宿正确**：运行流水留在本轮，私有事实留本地，通用规则回流到可分享的 Skill。

Skills 的调用次数、单次成功率或一次失败本身都不是经验；它们只是帮助发现模式的事实样本。

## 原子 memory

一条 memory 只对应一个根因，至少包含：

```markdown
---
id: stable-id
applies_to: [stage-or-skill]
status: active
---
# 人能理解的错误标题

- 现象：发生了什么。
- 根因：经验证的真正原因。
- 证据：代码、测试、命令结果或用户确认。
- 下次规则：下一次具体怎么改变决策。
- 适用边界：什么场景成立，什么场景不成立。
```

同一根因再次发生时更新原文，不追加重复日志。失效经验标记 `superseded` 或 `archived`。

## 决策轨迹不等于长期记忆

每一阶段都可以产出结构化决策轨迹，但轨迹默认属于本轮运行工件。只有被验证、去重且具有复用价值的根因才进入长期 memory。

这个区分防止 memory 退化为任务流水账。

同理，复盘和 Skills 使用清单也默认属于本轮运行工件。长期层只接收经过上述晋升门槛的原子结论。

## 私有经验与通用规则

- 环境、登录态、私有拓扑等事实进入被忽略的本地层；
- 通用且多次验证的方法上移到对应 Skill 或 reference，让分享出去的 Skill 同样受益；
- memory 不保存密钥，也不替代配置文件；
- 当前证据与旧经验冲突时，以当前证据为准并更新旧记忆状态。

## 停止规则

- **当前评审停止**：达到阈值，或完成第二轮主观评分；
- **复盘停止**：本轮事实已经覆盖目标、证据、Skills 使用和候选分流；不为“总结得更完整”反复改写；
- **记忆写入停止**：根因未验证、不可复现或已存在同根因条目。

有限评审保证速度，严格写入保证长期记忆质量。
