# 自进化 Skill 协议规范（Self-Evolving Skill Protocol）

> [!note] 历史归档
> 本文是较早的 **V1 轻量方案**，作为历史记录完整保留。它仍适用于使用 `experience.local.md` 单文件沉淀简单经验、仅面向本机环境的场景，但已不再是当前主题入口。当前设计理念与通用方法请阅读 [Skills Design Philosophy](../philosophy/README.md)。

> **一句话**：给 Skill 装上「越用越聪明」的能力——进 skill 先读一份本机经验当先验，干完活把新学到的写回去，下次不再从零试错。本文定义 V1 的轻量接入方式。

## 这份文档解决什么问题

普通 Skill 是一段**静态提示词**：你写好它，它每次都按同样的方式执行，踩过的坑下次还会再踩，摸到的窍门下次还得重新摸。

**自进化 Skill** 在静态提示词之外，多挂了一个**本机经验文件**。它把「在这台机器上真实跑通过的事实」沉淀下来，形成一个随使用不断变厚的记忆层。这正是现在常说的 **harness（驾驭层）工程**的内核：

> **协议（约束）保持不变，能力靠真实使用一点点长出来。**

本规范覆盖：核心理念 → 三条铁律 → 两种进化 → 文件约定 → 固化路径 → 门槛清单 → 接入套件（可直接复制）。

---

## 一、核心理念：harness = 约束不变，能力生长

一个自进化 skill 由两部分组成，**职责完全分开**：

| 部分 | 角色 | 进 git？ | 装什么 |
|------|------|---------|--------|
| `SKILL.md` | **框架 / 协议**（约束层） | ✅ 进，**可分享** | 通用流程、规则、占位符。**严禁出现任何真实值** |
| `experience.local.md` | **经验 / 记忆**（能力层） | ❌ 不进，**本机私有** | 这台机器的真实事实：IP、路径、登录态、踩过的坑、跑通的配方 |

一句话记住它们的关系：

> **SKILL.md 是可以分享给任何人的"骨架"；experience.local.md 是只属于你这台机器的"记忆"。骨架不变，记忆越长越厚。**

这套分层带来三个直接好处：

1. **可分享**：把 skill 分享给别人时，对方拿到的是干净的框架，不会泄露你的 IP / token / 内网拓扑。
2. **越用越快**：第二次用同一个 skill，它已经记得上次的主机清单 / 失败模式 / 有效配方，直接复用。
3. **自我保鲜**：当外部世界变了（网站改版、部署迁移），skill 在下次使用时把失效的经验标记掉、补上新解法。

## 二、三条铁律（机制的精髓）

整套机制最精妙的地方，可以浓缩成三条。**这三条是规范的核心，接入时必须原样遵守。**

### 铁律 1：读 = 规则强制，写 = AI 自主判断

| | 读取（Read） | 写入（Write） |
|---|---|---|
| 谁触发 | **SKILL.md 规则强制** | **AI 自己判断** |
| 何时 | 每次进 skill 的第一步，**必读** | 干完活、且**验证成功后** |
| 怎么实现 | 在 SKILL.md 里写死「Phase 0 先读 experience.local.md」 | 没有写入脚本，AI 用文件工具直接追加 |

最反直觉、也最关键的一点：

> **写入没有专门的脚本。** 写入行为完全由 SKILL.md 里的自然语言规则驱动，AI 在完成操作后**自主决定**写不写、写什么。读取则被规则**强制**触发。

为什么这样设计？因为「这次有没有冒出值得记的新东西」是个**判断题**，只有 AI 在上下文里才能判断；而「进 skill 要先读经验」是个**确定性动作**，必须强制、不能漏。

### 铁律 2：只写验证过的事实，不灌水

经验文件里**只许出现已经跑通、验证过的事实**，不许出现「可能」「大概」「应该能」这类未确认的猜测。

| 该写 | 不该写 |
|------|--------|
| 实测跑通的新用法 / 配方 | 没验证过的猜测 |
| 踩到的坑 + 根因 + 下次怎么绕 | 按预期正常工作的常规调用（这是默认行为，记了是噪音） |
| 被用户纠正过 ≥1 次的点（**必须写**） | 一次性的临时调试命令 |

> 判断标准只有一句：**这条经验对「下一次」还有用吗？** 没用就不写。**宁可沉淀得碎，也不要让真有用的经验流失；但绝不灌水。**

### 铁律 3：经验标注日期，当「可能有效的提示」而非「保证」

每条经验都标上发现/验证日期。下次读到它时，把它当作**可能有效的先验**——如果按它操作**失败了**，立即回退到通用做法，并把这条旧经验**改标为失败模式**（而不是默默忽略）。

这条保证了经验文件**自我纠错**：世界变了，经验跟着更新，不会越用越错。

## 三、两种进化：记得更多 vs 会得更多

进化分两种，**机制和风险护栏完全不同，绝不能混用同一套流程**：

| | **8a 经验沉淀型** | **8b 能力进化型** |
|---|---|---|
| 改什么 | 经验**数据**（experience.local.md） | skill **自身代码 / 工具** |
| 类比 | 长期记忆变厚 | 长出新器官 |
| 风险 | 低 | **高**（可能把现有能力改坏） |
| 触发 | **默认自动**（每次用完自问一句） | **重复摩擦达阈值 + 护栏**，不是想改就改 |
| 例子 | web-search 记住「本机有 <local-cli>」 | 给 agent-browser 加一个 `upload_files` 新能力 |

**一句话：8a 是"记得更多"，8b 是"会得更多"。**

> **大多数 skill 只需要 8a。** 它低风险、自动、收益稳定。本规范默认指 8a。

### 8b 的红线（要做能力进化必须卡死的护栏）

AI「随手改自己的代码」是极其危险的天性。**没有下面三道闸，禁止 8b：**

1. **阈值**：同一类「做不到」累计达阈值（默认 3 次重复摩擦）才进入候选，不是遇到一次就改。
2. **快照**：改任何代码前先 `git` 提交当前状态（或复制备份）。
3. **回归**：改完跑一遍既有典型流程，确认旧能力没坏；高风险改造必须**用户点头**。

## 四、文件与目录约定

### 4.1 经验文件：`experience.local.md`

**命名**：固定叫 `experience.local.md`，放在 skill 自己的目录下。
（同理，需要存密钥/配置的，用 `config.local.json`，同样不进 git。）

**文件头**（frontmatter / 抬头说明，照抄改名即可）：

```markdown
# <skill-name> 经验（本地私有 · 不进 git）

> 本文件由 <skill-name> skill 自动维护。进 skill 先读此文件当先验，用后把新学到的写回。
> 含真实 IP / 路径 / 登录态等敏感信息，**禁止提交到仓库**（已被 .gitignore 忽略）。
> 最近核实：<YYYY-MM-DD>
```

**正文结构**：不强求统一，按 skill 性质选最自然的。两种成熟范式：

- **表格台账型**（适合「清单 + 排查 + 套路」类，如 ssh-connect）：
  ```markdown
  ## 主机清单
  | 别名 | 连接命令 | 备注 |

  ## 连接排查经验
  | 现象 | 根因 | 处理 | 日期 |

  ## 工作流套路
  | 场景 | 套路 | 备注 |
  ```

- **配方流水账型**（适合「一条条可复现配方」类，如 opencli-harness）：
  ```markdown
  ### <站点/任务>：<一句话能做什么>
  - 状态：✅可用 / ⚠️残缺 / ❌走兜底  ｜ 最后验证：<YYYY-MM-DD>
  - 复现步骤：...
  - 坑：...
  ```

> 最小可用结构就三段式：**有效模式 / 失败模式 / 本机扩展**。一条经验写成「现象 → 根因 → 下次可执行规则」即可。

### 4.2 每个 skill 自带 `.gitignore`（关键，别漏）

约定是**在 skill 目录里放一个 `.gitignore`**，把本地文件挡在 git 之外。这样无论仓库根目录的 .gitignore 怎么写，这个 skill 的私有文件都不会被误提交：

```gitignore
# <skill>/.gitignore
config.local.json
experience.local.md
```

> ⚠️ 这一步最容易漏，漏了就会把真实 IP / token 提交进公开仓库。**接入第一步就建好它。**

### 4.3 路径解析的坑（`${CLAUDE_SKILL_DIR}` 会变空）

这是接入时**最容易踩的坑**，规范给统一结论：

- 在 SKILL.md 的**正文叙述**里，可以用 `${CLAUDE_SKILL_DIR}` 指代 skill 目录（可读性好）。
- 但在 **Bash 工具实际执行的命令**里，`${CLAUDE_SKILL_DIR}` **经常是空的**——它没被导出到 Bash 环境，会展开成空字符串，把路径变成 `/experience.local.md`，导致读写全部落空。

**统一解法**：在 Bash 命令里用「稳健解析」，别裸用 `${CLAUDE_SKILL_DIR}`：

```bash
# 稳健解析经验文件路径
SKILL_NAME="ssh-connect"                              # ← 改成你的 skill 名
DIR="${CLAUDE_SKILL_DIR:-}"
[ -z "$DIR" ] && DIR="$(dirname "$(find "$HOME/.claude" -name SKILL.md -path "*/$SKILL_NAME/*" 2>/dev/null | head -1)")"
[ -z "$DIR" ] && DIR="$HOME/.claude/skills/$SKILL_NAME"   # j-skills 默认安装位置兜底
EXP="$DIR/experience.local.md"

[ -f "$EXP" ] && sed -n '1,80p' "$EXP" || echo "经验文件不存在 → 走首次初始化分支"
```

> 简化版（你确定 skill 用 j-skills 装在默认位置）：直接写死 `EXP="$HOME/.claude/skills/$SKILL_NAME/experience.local.md"`。

### 4.4 SKILL.md 里**严禁出现真实值**

这是分层的底线，必须在 SKILL.md 用 `<constraint>` 写死：

> SKILL.md 严禁出现任何真实的 host/IP、绝对路径、用户名、仓库名、token、代理端口——一律用 `$VAR` 或 `<占位符>`。真实值**只存** experience.local.md（gitignored）。

## 五、固化路径：从经验回流到 SKILL.md（分享型 skill 必看）

这一条专门针对**要分享给别人的 skill**，是很多人会忽略、但极其重要的一环。

experience.local.md 是**你这台机器私有的**。如果一条经验是**通用的**（对所有人都成立，不是机器相关的事实），它就**不该只躺在你的本地经验文件里**——否则会出现：

> **你这台机器越用越聪明，但分享出去的 skill 对别人还是初版。** 进化全锁死在了你本地。

所以要区分经验的两种归宿：

| 经验类型 | 归宿 | 例子 |
|---------|------|------|
| **机器/环境相关的事实** | 留在 `experience.local.md` | 「我这台机器的远端主机是 <host-ip>」「本机有 <local-cli>」 |
| **通用的方法 / 规则 / 坑** | **固化进 SKILL.md**（等于发 PR，对所有人生效） | 「读小红书 web_reader 一律返回空，要走浏览器兜底」 |

**操作建议**：当一条经验被反复验证为「通用规则」时，把它**并入 SKILL.md 正文**，并在 experience.local.md 里把原条目标注「已固化进 SKILL.md」。这样能力既保鲜、又能随 skill 分享出去。

> 这也呼应一条更高层的原则：**分享型 skill 的"进化"，首选目标是固化进 SKILL.md，而不是写进个人的本地经验/记忆。** 本地经验只装真正机器私有的部分。

## 六、门槛清单：哪些 skill 该接，哪些不该接

**不是所有 skill 都该接这套机制。** 它有成本（每次进 skill 多读一个文件、AI 每次要判断写不写），只在特定条件下回本。接错了反而是负担和噪音。

### ✅ 该接（强相关，三选一即可）

- **环境耦合型**：依赖本机状态 / 登录态 / 拓扑。这些「关于这台机器的事实」本来就塞不进可分享的 SKILL.md。
  - 例：ssh-connect（主机清单）、web-search（本机有哪些 CLI）、remote-dev-sync（两端环境）、happy-ops（部署拓扑）
- **高摩擦型**：反复踩同类坑，失败模式值得记下来避开。
  - 例：opencli-harness（官方 adapter 残缺，要记 CDP 绕法）、github-repo-publish（沙箱代理坑）
- **高频型**：用得多，沉淀才有复利。低频 skill 沉淀永远攒不够。

### ❌ 不该接（接了就是灌水）

- **纯变换型 / 无状态 / 确定性**：同输入同输出，根本没有「环境」可学。
  - 例：翻译类、PDF 处理、纯模板出图（gpt-image 模板）
- **一次性 / 低频**：用不了几次，经验文件长期是空的。
- **经验本该固化进 SKILL.md 的**：如果学到的东西是通用规则，直接进 SKILL.md（见第五节），不需要本地经验文件。

> **决策一句话**：这个 skill 会不会「在不同机器/环境上表现不同」「反复踩同类坑」「被高频使用」？三个都不沾 → 不要接。

## 七、接入套件（可直接复制）

给一个**符合门槛**的 skill 接入自进化，只需三步。

### 步骤 1：建 `.gitignore`（挡住私有文件）

在 skill 目录下新建 `.gitignore`：

```gitignore
config.local.json
experience.local.md
```

### 步骤 2：在 SKILL.md 里加「经验沉淀」一节（约 25 行）

把下面这段贴进 SKILL.md（改掉 `<skill-name>` 和结构）。**它同时定义了读、写、回退三件事**：

```markdown
## 经验沉淀机制（自我进化）

经验存储在 `experience.local.md`（gitignored、本机私有、含真实值），由你（LLM）自动维护。
路径解析见下方 Bash（别裸用 ${CLAUDE_SKILL_DIR}，Bash 环境里它常为空）。

### 读取（每次进 skill 必做）
进 skill 第一步**必须先读** experience.local.md，把里面的经验逐条当作本次的先验/检查项。
优先级：本机扩展 > 失败模式 > 有效模式。

### 写入（干完活、验证成功后，AI 自主判断）
出现下列任一就**主动**追加写回，否则不写（不灌水）：
- 实测跑通了某个新用法 / 新配方
- 踩到新坑（记：现象 → 根因 → 下次可执行规则）
- 既有经验失效了（标「⚠️ 待复核」并补新解法）
- **被用户纠正过 ≥1 次 → 必须写**
只写验证过的事实，不写猜测；常规正常调用不记。

### 回退
按经验操作失败 → 立即回退通用做法 → 把那条旧经验改标为「失败模式」。
```

并在 SKILL.md 顶部加一条约束：

```markdown
<constraint>SKILL.md 严禁出现真实 host/IP/路径/token/端口，一律用占位符；真实值只存 experience.local.md</constraint>
```

### 步骤 3：在 SKILL.md 的流程里放好读写时机

- **Phase 0 / 第一步**：放第 4.3 节的「稳健解析路径 + 读经验」Bash 块。
- **最后一个 Phase**：放一句「本轮有没有冒出值得记的新东西？有就按写入规则追加 experience.local.md」。

经验文件本身**不用预先创建**——第一次运行时若不存在，AI 按文件头模板（4.1）新建即可。

## 八、自检清单 & 反模式

接入后对照检查：

- [ ] skill 目录有 `.gitignore`，挡住了 `experience.local.md` / `config.local.json`
- [ ] SKILL.md 里**没有**任何真实 IP / token / 绝对路径（全是占位符）
- [ ] Bash 命令里**没有裸用** `${CLAUDE_SKILL_DIR}`（用了稳健解析或写死路径）
- [ ] 流程明确：**进 skill 必读经验**（强制）、**干完活判断是否写回**（自主）
- [ ] 写入规则写明了「只写验证过的事实，被纠正过 ≥1 次必写，常规调用不记」
- [ ] 想清楚了这个 skill **是否真该接**（过了第六节门槛）

**反模式（别犯）**：

| 反模式 | 后果 | 正解 |
|--------|------|------|
| 给无状态 skill 也接 | 经验文件长期空，纯负担 | 过门槛再接 |
| 把真实值写进 SKILL.md | 分享时泄露 / 别人用不了 | 真实值只进 experience.local.md |
| 灌水式记录（常规调用也记） | 经验文件越来越吵，先验失效 | 只记「下次还用得上」的 |
| 通用规则只留在本地经验 | 你聪明了，分享出去还是初版 | 固化进 SKILL.md（第五节） |
| 让 AI 随手改自己代码（8b）无护栏 | 改坏现有能力 | 阈值 + 快照 + 回归三道闸 |
