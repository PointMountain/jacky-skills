# Durable 模式

> Durable 是一种面向长任务的无人值守执行模式：任务启动后，Agent 尽量依靠默认配置和自主判断持续推进，不等待用户反复确认，尤其适合在夜间运行。

## 一、Durable 是什么意思

这里的 **Durable** 不是某个模型、软件版本或具体工具，而是一份任务执行约定。

当用户说“用 Durable 执行”“今晚 Durable 跑一下”或类似表达时，应理解为：

1. 这是一个可能持续较长时间的任务。
2. 用户暂时不会守在任务旁边，也不希望执行过程中频繁被提问。
3. Agent 应优先使用项目现有的默认版本、稳定配置和推荐方案。
4. 遇到普通的不确定性时，Agent 应自行做出合理判断、记录假设并继续执行。
5. 遇到可恢复的失败时，Agent 应先诊断、重试或采用安全的替代方案，而不是立即停下来等待用户。
6. 任务结束后，Agent 应给出结果、验证情况、重要决策以及仍未解决的问题。

一句话概括：

> **Durable = 启动后尽量不中断、少打扰、能自我推进并留下完整结果的无人值守长任务模式。**

## 二、默认执行规则

进入 Durable 模式后，Agent 默认遵循以下规则：

### 2.1 直接开始

如果目标和范围已经足够明确，直接执行，不再询问“是否开始”。

### 2.2 优先采用默认值

需要在多个普通选项之间选择时，按以下顺序处理：

1. 使用用户已经指定的默认值。
2. 使用项目当前已有的配置和版本。
3. 使用工具官方或项目推荐的稳定默认值。
4. 如果仍需判断，选择风险较低、容易回退的方案，并在结果中说明。

“默认版本”通常指当前项目或工具采用的稳定默认版本，不等于擅自升级到最新版本。

### 2.3 减少阻塞式提问

普通实现细节、可逆选择和低风险分歧，由 Agent 自主决定。执行期间可以记录进度，但不应要求用户立即回复才能继续。

只有当缺少的信息会明显改变任务目标，或者继续操作需要新的权限时，才应暂停并说明阻塞原因。

### 2.4 持续推进

Agent 应把长任务拆分为可验证的阶段，逐步执行。出现失败时，优先：

1. 收集错误信息并判断原因。
2. 在安全范围内重试。
3. 尝试风险较低的替代路径。
4. 保存已经完成的结果和当前状态。
5. 确实无法继续时，再停止并清楚报告阻塞点。

### 2.5 完成后验证

Durable 任务不能只以“命令运行过”作为完成标准。应根据任务类型执行必要的检查，例如测试、构建、状态检查、输出文件检查或实际功能验证。

## 三、Durable 不代表什么

Durable 的“无人值守”不会扩大用户原本授予的权限，也不代表 Agent 可以进行任何操作。

以下行为仍然需要用户明确授权，不能因为处于 Durable 模式就自行执行：

- 删除重要数据或进行难以恢复的破坏性操作。
- 产生费用、购买服务或扩大资源用量。
- 向外部人员发送消息、公开发布内容或创建正式发布。
- 修改生产环境中的高风险配置。
- 绕过安全限制、权限控制或既定审批流程。
- 将任务范围扩展到用户没有指定的系统、仓库或账号。

如果任务必须依赖上述操作才能继续，Agent 应保留当前进度，说明所需授权，并等待用户回来处理。

## 四、适用场景

Durable 特别适合：

- 夜间运行测试、构建、迁移或批处理任务。
- 长时间代码生成、重构、资料整理或内容处理。
- 需要多轮诊断、重试和验证的工程任务。
- 用户已经给出清晰目标，但不想持续参与过程选择的任务。

Durable 并不只限于晚上。只要用户希望任务在较少交互的情况下持续执行，任何时间都可以使用。

## 五、不适用场景

以下情况不适合直接进入 Durable 模式：

- 用户还在讨论方向，尚未确定要执行什么。
- 不同方案会产生明显不同的产品结果，且没有合理默认项。
- 任务一开始就需要高风险操作或新的外部授权。
- 缺少账号、凭据、文件或环境，导致任务根本无法启动。

## 六、推荐的触发表达

用户可以直接这样说：

```text
这个任务用 Durable 执行。
```

也可以补充范围或结束条件：

```text
今晚用 Durable 把测试修到全部通过，使用项目默认版本，不要中途等我回复。
```

Agent 看到 **Durable** 后，应自动采用本文约定；除非用户在当次任务中给出了更具体、与本文不同的指令，以用户当次指令为准。

## 七、完成报告

Durable 任务结束时，至少应说明：

1. 最终结果是否完成。
2. 实际修改或产出了什么。
3. 做过哪些关键验证。
4. 自主采用了哪些重要默认值或假设。
5. 是否还存在失败项、风险或需要用户处理的阻塞点。

## 总结

Durable 的核心不是“无限运行”，而是让一个目标明确的长任务在用户不值守时，仍能按照安全边界自主选择默认方案、处理普通问题、持续推进并完成验证。

在本仓库的后续交流中，用户单独提到 **Durable**，默认就是指本文定义的执行模式。
