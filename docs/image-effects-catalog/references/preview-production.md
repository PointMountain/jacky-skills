# Image Effects Preview Production SOP

本 SOP 用于批量新增或重做 `image-effects` Gallery 预览。它只约束预览制作，不改变效果运行协议、来源与许可证契约或发布门禁。单次只处理一张预览时，也沿用相同的重试和验收边界。

## 目标与时间预算

- 七张独立预览默认并发制作，目标在 10–20 分钟内完成生成、统一处理和集中验收。
- 执行 10 分钟后仍未得到首轮全部结果时，报告已完成数量、当前阻塞和预计剩余时间。
- 20 分钟后仍未完成时，停止扩大精修范围，只处理硬失败。
- 30 分钟仍未完成时暂停任务并向用户说明原因；不得静默增加生成轮次、验收指标或制作阶段。
- 图片服务排队、限流或故障不计为正常制作耗时，但必须即时报告，不能用额外生成请求掩盖。

## 开始前冻结输入

在调用图片工具前，一次性确认：

1. 待制作的效果清单和每张最终文件名。
2. 每张预览的方向与精确像素尺寸。
3. 每个效果的独立虚构主题，以及禁止出现的人物身份、品牌、商标、已知角色和第三方摄影内容。
4. 哪些文字必须逐字准确；没有明确要求时，不主动增加文字。
5. 哪些效果确实需要本地排版。除已批准的 Editorial Echo 两阶段流程外，默认直接生成最终预览。

上述信息已经存在于批准的设计或效果卡时直接读取，不再询问用户。只有会改变结果的决策缺失时，才逐个确认。

## 并发分工

七张预览默认使用三个互不重叠的 Worker，按 `3 / 2 / 2` 分配；主 Agent 只负责协调、集中验收和最终写入。

每个 Worker 必须遵守：

- 只处理分配给自己的效果，不接手或重做其他 Worker 的图片。
- 输出到独立临时目录和唯一文件名，不修改共享卡片、索引、生成目录或 Git 状态。
- 不提交 Git，不移动其他 Worker 的文件，不启动独立 Reviewer。
- 同一效果不能由多个 Worker 同时生成，以免产生重复调用和选择成本。
- 完成后只返回最终候选文件、所用提示、是否重试以及可见硬失败说明。

如果环境不允许可靠并发，则退化为顺序生成，但仍使用同一份冻结清单，并在开始前报告预计耗时。

## 生成与重试

1. 每个效果首轮只生成一个候选，不生成多张供挑选。
2. 不复用旧 Gallery 示例、用户附件、真人照片、品牌素材或第三方预览图。
3. 不把某个效果的最终预览作为另一个效果的输入。
4. 只有硬失败可以触发一次定向重试；重试提示只修复已识别的问题，不重新设计整张图片。
5. 图片服务调用被中断时，先确认原调用是否已经完成；不得在状态未知时重复提交。
6. 同一效果最多一次生成重试。需要第二次重试或新增制作阶段时，必须先向用户说明原因并获得确认。

硬失败包括：

- 方向、尺寸或文件格式不符合约定。
- 文件不能完整解码，或包含禁止的 EXIF、XMP、GPS、设备信息、文本块或尾随数据。
- 出现可见水印、签名、Logo、品牌、真实身份或明确的第三方作品来源风险。
- 必须准确的文字缺失、错字或不可辨认。
- 主体严重畸形，或效果方向无法识别。
- 违反批准设计中明确写出的硬构图规则。

以下情况默认属于软偏好，不触发自动重试：

- 颜色、留白或元素比例与参考值只有轻微偏差。
- 某个构图版本可能更漂亮，但当前版本已经清楚表达效果。
- 为了统一风格而继续精修已经合格的图片。

## 集中处理与验收

首轮并发完成后，由主 Agent 一次性处理全部候选：

1. 使用项目已有工具统一旋转、缩放、扁平化透明通道、移除元数据并输出最终 PNG 或 JPEG；不为本次任务新增一次性处理脚本。
2. 批量检查完整解码、精确尺寸、格式和禁止元数据。
3. 以一轮集中视觉检查确认效果可辨识、彼此有区分，并且没有明显水印、签名、Logo、来源风险或严重构图错误。
4. 只对硬失败图片发起定向修复；合格图片不得因为 Reviewer 的个人审美偏好重新生成。
5. 全部通过后再统一记录 SHA-256、尺寸、`preview_origin`、作者和许可证，并一次性写入仓库。
6. 最终只运行与预览资产直接相关的测试；完整仓库测试留给合并前发布门禁。

默认不执行自定义像素占比、颜色面积、凸包、留白比例等量化分析。只有批准设计明确要求机器阈值、现有测试已经实现该检查，或用户明确要求精确测量时才使用。近似视觉目标优先通过集中目视判断。

## 禁止的低效模式

- 为每张图片创建独立 Task、brief、报告、Implementer 和 Reviewer。
- 七张图片由一个 Worker 串行生成，而并发资源处于空闲状态。
- 为同一效果并发生成多个候选再做主观选图。
- 图片已经满足硬门槛后继续自动美化、扩写提示或增加验证项目。
- 每修改一张图片就运行完整测试、重建全部 Gallery 或进行一次浏览器验收。
- 为证明近似视觉目标而临时编写复杂测量逻辑。
- 因工具调用等待或客户端中断而盲目重复付费或有配额消耗的请求。

## 完成交付

交付说明保持简短，只报告：

- 完成与返修的图片数量。
- 是否全部通过硬验收。
- 是否存在服务限流、工具故障或用户需要决定的例外。
- 最终资产和直接相关测试的状态。

不要把内部逐步操作、临时文件、每张图的主观评价或重复测试日志堆入交付说明。
