# WebFlow 外部能力

> 这里定义能力槽位和选择规则，不固定某一批 Skill 名单。当前环境会变化，运行时应从可用目录按语义选择。

## 一、按需选择原则

1. 只有当前阶段需要某种能力时才查找，不在 run 开始时全量探测。
2. 从当前 Skill/工具目录中选择最符合槽位语义的候选，一次只探测首选项。
3. 最小探测必须产生可复核证据；目录存在、说明自称可用或命令零退出码都不充分。
4. 首选失败才换下一个候选；没有候选时执行本地 fallback，不因装饰性能力阻断核心网站。
5. 同一 run 复用已验证结果；能力失败或证据过期才刷新。
6. 把选择、证据、fallback 和实际使用情况写入 `skill-usage.md`，不得写凭证、私有 URL 或用户绝对路径。

## 二、语义槽位

| 槽位 | 何时需要 | 最小证据 | 本地 fallback |
| --- | --- | --- | --- |
| `reference_observation` | 需要观察参考网页结构、视觉或交互 | 可复核页面结构、截图或录屏帧 | 使用用户提供的源码、截图和文字证据 |
| `prototype_design` | 需要可打开的 wireframe 或高保真 prototype | 本地原型可打开，桌面与移动视图可检查 | 直接编写本地 HTML/CSS 原型 |
| `visual_asset_generation` | 内容规格明确需要原创视觉素材 | 文件真实存在，尺寸、格式和用途匹配 | CSS、SVG 或已有授权素材 |
| `browser_verification` | build 阶段验证真实页面 | HTTP 成功、桌面/移动截图、控制台结果 | 使用当前可用浏览器手动检查并记录证据 |
| `deployment_provider` | 用户已请求并授权真实发布 | 预检证明认证、项目和目标可用 | 不部署，保留已批准 preview 并说明阻断 |

## 三、失败处理

探测或调用失败时，先记录失败事实和对当前阶段的影响，再选择 fallback。只有缺失能力使 must-pass 事实无法验证时才阻断；视觉资产生成等可替代能力不应成为默认硬依赖。

安装新插件、登录第三方服务、创建远端项目或产生费用都属于新的外部状态变更，必须遵守当前任务授权边界。部署额外遵守[工作流导航](workflow.md)的 G3 后授权规则。
