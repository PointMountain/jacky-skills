# 教程提取协议

> 把教程媒体转换为可复核的方法事实与动效事实。只执行当前输入触发的卡片；每张卡都留下可定位、可哈希、可复验的证据。

## 目录

1. 来源摄取
2. 音轨识别
3. 时间码字幕
4. cue 复核
5. 粗抽帧
6. 关键段密集抽帧
7. 小主体放大
8. 屏幕代码取证
9. 事实分层
10. method/motion 交接
11. 异常回退与候选

## 使用规则

- 先读 `ingest.json` 和真实媒体，再决定触发哪些卡片；不要为未发生的步骤制造空证据。
- 证据使用 run 内相对路径并绑定文件 SHA-256。字幕、截图和工具输出只是证据，不能自动升级为结论。
- 每个判断写出它依赖的 cue、时间范围、帧或代码证据。无法复核时降级为候选，不用推断填空。
- 原媒体、完整字幕、私人画面和本机绝对路径只留在被忽略的私有 run 中。

## 卡片 1：来源摄取

- **触发**：收到本地视频、独立的配对音轨或公开视频 URL。
- **输入**：用户给定来源、授权边界、可选配对关系与目标 run。
- **观察**：确认容器可读性、音视频流、时长、尺寸、帧率，以及配对音轨与视频时长是否吻合。
- **证据**：保存来源类型、探测回执、真实媒体字节 SHA-256 和安全 source ID。
- **判断**：选择本地直读、视频加配对音轨或 URL 摄取路径；URL 字符串 hash 不能代替媒体 hash。
- **行动**：取得 run 内可读媒体，保留原始输入，不做不可逆覆盖。
- **产物**：`ingest.json`、媒体探测回执和私有来源文件引用。
- **Must-pass**：来源已授权、至少一个媒体流可读、记录的是实际媒体字节 hash。
- **Fallback**：URL 无法摄取时保存错误与候选能力；配对不可信时分开处理并标记待确认。

## 卡片 2：音轨识别

- **触发**：媒体含语音，或用户提供了与视频配对的独立音轨。
- **输入**：已摄取媒体、音轨索引、语言提示和可用本地转录能力。
- **观察**：检查采样率、声道、语音区间、静音区间以及音画时长偏差。
- **证据**：保存音轨探测结果、提取回执、工具标识与输出 hash。
- **判断**：决定直接转录、先抽取音轨、按区间切片或使用配对音轨。
- **行动**：通过运行时能力路由调用本地 ASR；不把某台机器的安装路径写进共享文档。
- **产物**：私有标准化音频或原音轨引用，以及转录工具回执。
- **Must-pass**：被识别音轨可解码，且与来源和媒体 hash 绑定。
- **Fallback**：首选 ASR 失败时仅探测适用候选；全部失败则记录日志并 `blocked`。

## 卡片 3：时间码字幕

- **触发**：已有可识别语音，需要把讲授步骤定位到时间轴。
- **输入**：来源绑定的音轨、ASR 输出和媒体总时长。
- **观察**：检查每个字幕片段的起止时间、文本、重叠、越界和异常长空档。
- **证据**：为每个 cue 保存稳定 cue ID、起止秒数、文本和转录文件 hash。
- **判断**：判断字幕能否支撑教程步骤导航；低置信内容不得伪装成教程原话。
- **行动**：标准化为按时间递增、边界合法、可由 cue ID 引用的时间码字幕。
- **产物**：`transcript.json` 和被其 hash 绑定的私有完整转录。
- **Must-pass**：cue 非空、时间码合法、最后一个 cue 不越过媒体时长容差。
- **Fallback**：无语音教程标记为视觉主导；局部不可辨识则保留时间窗与待复核标记。

## 卡片 4：cue 复核

- **触发**：时间码字幕已生成，准备据此提炼教程方法。
- **输入**：`transcript.json`、原音轨和疑似关键步骤的 cue 集合。
- **观察**：回听关键 cue，核对术语、数字、先后关系、否定词和代码名称。
- **证据**：记录复核 cue ID、原值、修订值、复核时间窗与音轨 hash。
- **判断**：区分可确认原话、语义摘要和仍不确定内容。
- **行动**：只纠正有音频证据支持的内容；把不确定项留作候选。
- **产物**：已复核 cue、修订记录和关键时间段清单。
- **Must-pass**：进入 `tutorial_fact` 的语句都能回到已复核 cue 和真实音轨。
- **Fallback**：音频证据不足时降低结论强度，并用画面或屏幕代码交叉验证。

## 卡片 5：粗抽帧

- **触发**：媒体含画面，需要建立完整时间轴的视觉导航。
- **输入**：可读视频、媒体时长和转场密度初步估计。
- **观察**：检查全片构图、界面状态、主要镜头、章节变化和可能的动效区间。
- **证据**：保存覆盖全时长的顺序接触表、采样清单、时间码与每张图 hash。
- **判断**：标出值得密采的变化区间；均匀抽帧只能导航，不能证明运动细节。
- **行动**：以足以覆盖开头、中段和结尾的低频采样生成粗看材料并亲自查看。
- **产物**：粗抽帧清单、接触表和关键段候选列表。
- **Must-pass**：证据覆盖全时长，顺序与时间码可复验，没有只看首尾就下结论。
- **Fallback**：解码不稳定时保存失败时间点，换用无副作用的兼容解码路径后重试。

## 卡片 6：关键段密集抽帧

- **触发**：粗抽帧发现转场、镜头运动、形变、遮罩或节奏变化。
- **输入**：关键段候选、原视频和需要回答的具体运动问题。
- **观察**：比较起始态、主要过渡中段、稳定态与退场，识别方向、速度、缓动和层级关系。
- **证据**：保存高密度顺序帧带、精确时间窗、采样率、问题描述与文件 hash。
- **判断**：只从连续帧支持的变化推导 `visual_observation`，不从单帧猜动画。
- **行动**：针对每个未解运动问题缩小时间窗并提高采样密度，直到证据足够或明确不足。
- **产物**：关键段帧带、时间关系摘要和待放大区域候选。
- **Must-pass**：每个主要过渡至少覆盖开始、变化中段、稳定和退出四类状态。
- **Fallback**：仍无法判断时保留多个实现候选，不把最顺眼的一个写成教程事实。

## 卡片 7：小主体放大

- **触发**：关键动作只占画面小区域，原尺寸不足以判断位移、遮挡或代码变化。
- **输入**：原帧、目标区域、关键时间窗和待回答问题。
- **观察**：确认主体边界、局部位移、像素变化、遮挡顺序及其与全局画面的同步关系。
- **证据**：同时保留原帧和放大 crop，记录 crop 坐标、缩放倍率、时间码与两者 hash。
- **判断**：放大只能提高可见性，不能补出源画面不存在的细节。
- **行动**：使用确定性 crop/scale 生成对照帧带，并与全局帧并排查看。
- **产物**：局部放大证据、区域清单和经确认的局部观察。
- **Must-pass**：每个 crop 可追溯到原帧，坐标未裁掉判断所需上下文。
- **Fallback**：压缩损失过大时标记不可判定，转向字幕、代码或更多邻近帧交叉验证。

## 卡片 8：屏幕代码取证

- **触发**：教程展示代码、参数、时间线、节点层级或命令，且它们影响方法理解。
- **输入**：代码出现时间窗、原始画面、字幕 cue 与可能的多帧滚动内容。
- **观察**：识别可见标识符、数值、调用关系和前后编辑变化，不补全画面外代码。
- **证据**：保存原帧、必要的局部放大、时间码、转录文本和人工复核结果。
- **判断**：只有画面直接可读且复核过的内容进入 `code_fact`；推测的缺失部分进入 `implementation_inference`。
- **行动**：逐段抄录最小可证代码片段，并用相邻帧确认被遮挡或滚动的行。
- **产物**：代码证据清单、`code_fact` 记录和不确定片段候选。
- **Must-pass**：每条代码事实都有可读画面证据，大小写、符号和数值经过复核。
- **Fallback**：无法可靠识别时只记录行为效果和时间窗，不输出伪精确代码。

## 卡片 9：事实分层

- **触发**：字幕、视觉帧或屏幕代码已经产生可用证据。
- **输入**：已复核 cue、关键帧、代码证据和实现约束。
- **观察**：识别结论究竟来自教程讲述、画面直接变化、可读代码还是实现者推断。
- **证据**：为每条结论绑定来源类型、source ID、媒体 hash、时间范围和具体证据路径。
- **判断**：严格分为 `tutorial_fact`、`visual_observation`、`code_fact`、`implementation_inference`，不得跨层冒充。
- **行动**：拆开同时包含事实和推断的句子；冲突时保留冲突及各自证据。
- **产物**：分层事实集合、冲突清单和实现假设候选。
- **Must-pass**：每条结论只有一个明确类型，且引用的 cue、帧或代码证据真实存在并可哈希。
- **Fallback**：来源不够明确时降级到 `implementation_inference` 或候选，不强行归为教程事实。

## 卡片 10：method/motion 交接

- **触发**：事实分层完成，准备规划可实现的 Demo。
- **输入**：分层事实、教程因果步骤、连续帧观察和素材约束。
- **观察**：检查“为什么这样做”的方法链与“画面怎样变化”的时间链是否分别完整。
- **证据**：让每个方法结论和运动结论引用其直接 cue、代码或帧证据。
- **判断**：方法语义进入 method，空间、状态和时间关系进入 motion；本地设计选择不冒充来源事实。
- **行动**：生成 `method-spec.json` 与 `motion-spec.json`，再交给 `plan_demo`，不直接跳到实现。
- **产物**：`method-spec.json`、`motion-spec.json` 和未解决问题列表。
- **Must-pass**：两份 handoff 均绑定同一真实媒体，关键结论有证据，且能指导 Demo 规划。
- **Fallback**：方法或运动任一不足时返回对应卡片补证，不用实现结果倒推来源结论。

## 卡片 11：异常回退与候选

- **触发**：任一卡片的输入不可读、能力失败、证据矛盾或 Must-pass 不成立。
- **输入**：失败步骤、命令回执、输入 hash、当前判断与适用能力目录。
- **观察**：区分来源问题、工具缺失、环境漂移、证据不足、隐私风险和真实方法歧义。
- **证据**：保存退出码、标准输出/错误 hash、失败时间点与已尝试候选，不只写自然语言结论。
- **判断**：只选择对当前输入适用且 probe 无副作用的候选；失败不是降低证据标准的理由。
- **行动**：按能力路由尝试最小回退，或将未证实做法写为候选并明确下一验证动作。
- **产物**：失败回执、回退选择、候选记录，或带理由的 `blocked` 状态。
- **Must-pass**：回退不下载、不安装、不覆盖原输入，不把失败步骤伪装为完成。
- **Fallback**：所有适用候选失败、来源未授权或隐私边界无法满足时停止并请求外部条件变化。
