# 站点经验沉淀机制：从 SKILL.md 规则到自动化读取的完整链路

> 本文是本 skill「经验沉淀（持续机制）」一节的设计来源，原型来自 web-access 项目的站点经验系统。核心一句话：**写入 = Prompt 驱动的 AI 自主行为，读取 = 规则强制**。本 skill 把同一思想搬到 `references/lessons.md`，只是把"按域名分文件"简化为"单文件流水账"。

## 问题

一个 skill 如何实现经验沉淀？经验文件从"空目录"到"有内容"的完整流程是什么？谁负责写、谁负责读？

## 核心发现：写入是 Prompt 驱动的 AI 行为，读取是脚本/规则驱动的自动化行为

这个机制最精妙的地方在于：**写入经验文件没有一个专门的脚本**。写入行为完全由 SKILL.md 中的自然语言规则驱动，AI 在完成操作后自主决定是否写入。而读取则被规则（或脚本）强制触发。

```
SKILL.md（规则定义）
    ├── 定义了经验文件的格式（frontmatter + 正文结构）
    ├── 定义了什么时候读（确定目标 / 进入 skill 时）
    ├── 定义了什么时候写（操作成功后）
    └── 定义了写什么（只写经过验证的事实）
         │
         ▼
┌─────────────────────────────────────────┐
│         AI 的行为（Prompt 驱动）          │
│                                         │
│  读取 ← 规则/脚本强制                     │
│  写入 ← AI 自主判断（Prompt 规则驱动）     │
│  暴露 ← 启动时展示已有经验                 │
└─────────────────────────────────────────┘
         │
         ▼
经验文件（本 skill 中为 references/lessons.md）
```

## 一、规则定义：SKILL.md 中的「站点经验 / 经验沉淀」一节

原型项目用约 25 行定义了整个机制的核心规则，要点如下。

### 1.1 存储位置

操作中积累的经验集中存放在 `references/` 下。原型按域名分文件（`juejin.cn.md`），本 skill 简化为单文件 `references/lessons.md`，一条经验一段。

### 1.2 读取触发时机（强制）

确定目标后，如果存在匹配的经验，**必须读取**对应内容获取先验知识。关键词是"必须"——AI 被强制要求在操作前先读取已有经验。

### 1.3 读取失败时的回退策略

经验内容标注了发现日期，当作**可能有效的提示而非保证**——如果按经验操作失败，回退通用模式并更新经验文件。

### 1.4 写入触发时机（主动）

操作成功完成后，如果发现了有必要记录的新模式，**主动写入**。关键词是"主动写入"和"成功完成后"——写入是 AI 的自主行为，且必须在操作成功验证后才写。

### 1.5 写入约束

**只写经过验证的事实，不写未确认的猜测。** 这是质量保障：经验文件里不会出现"可能"、"大概"之类的内容。

### 1.6 文件格式模板（原型：按域名分文件）

```markdown
---
domain: example.com
aliases: [示例, Example]
updated: 2026-03-19
---
## 平台特征
架构、反爬行为、登录需求、内容加载方式等事实

## 有效模式
已验证的 URL 模式、操作策略、选择器

## 已知陷阱
什么会失败以及为什么
```

三个 section 的设计逻辑：先说"是什么"（平台特征），再说"什么行"（有效模式），最后说"什么不行"（已知陷阱）——信息层次清晰。本 skill 把它压缩成单条三段式：**现象 → 根因 → 下次可执行规则**。

## 二、写入机制：Prompt 驱动的 AI 行为

### 2.1 没有写入脚本

整个项目中**不存在专门用于写入经验文件的脚本**。写入操作由 AI 直接执行文件写入。

### 2.2 写入流程

```
AI 完成操作（如本 skill 完成一次动效反推）
    │
    ▼
AI 自主判断：是否有必要记录？
    │
    ├── 否（顺利无新发现） → 跳过，任务结束
    │
    └── 是 → AI 执行写入
              │
              ├── 新文件 → 按模板创建并填写 frontmatter 和正文
              │
              └── 已有文件 → 读取现有内容，追加新经验段落，更新日期
```

### 2.3 写入判断依据

| 场景 | 是否写入 |
|------|----------|
| 发现了新的有效模式 | 写入"有效模式 / 下次规则" |
| 某种常见做法失败了 | 写入"已知陷阱" |
| 本轮被用户纠正过 ≥1 次 | **必须写入对应经验** |
| 一切顺利，没有特殊发现 | 不写入（不灌水） |

## 三、读取机制：规则 / 脚本强制

原型用一个 ~47 行的 `match-site.mjs` 做域名+别名正则匹配，输出经验正文；启动时另有脚本列出已有站点经验，让 AI 知道当前有哪些经验可用。

本 skill 不需要脚本——读取由 SKILL.md 规则强制：**每次进入 skill，Phase 0 第 0 步必须先读 `references/lessons.md`，逐条把"下次规则"作为本次检查项**。规则即引擎。

关键设计细节（原型脚本层面，供理解机制）：

- **正则转义**：域名中的 `.` 在正则里是"任意字符"，必须转义为 `\.` 才能精确匹配。
- **Frontmatter 跳过**：找到第二个 `---` 之后的内容输出，跳过 frontmatter；没有 frontmatter 则输出全部。
- **多站点循环**：遍历所有经验文件，用户输入可能同时命中多个，全部输出。

## 四、完整数据流

```
┌─── 初始状态 ───┐       references/lessons.md 为空或只有占位
└────────────────┘
        │ 第一次运行 skill
        ▼
┌─── AI 操作 + 判断 ───┐
│  1. 读经验 → 空，无先验  │
│  2. 执行任务            │
│  3. AI 判断："发现了    │
│     一个值得记录的坑"    │
└──────────────────────┘
        │ AI 主动写入
        ▼
┌─── 写入后状态 ───┐     references/lessons.md 多了一条三段式经验
└──────────────────┘
        │ 第二次运行
        ▼
┌─── 读取已有经验 ───┐
│  1. 读经验 → 命中     │
│  2. 逐条当检查项过    │
│  3. 避开已知陷阱执行   │
│  4. AI 判断：         │
│     "发现新陷阱"→追加  │
│     "一切顺利"→不修改  │
└────────────────────┘
```

## 五、迁移到本 skill 的差异

| 维度 | 原型（web-access） | 本 skill（animate-prompt） |
|------|--------------------|----------------------------|
| 存储 | 按域名分文件 `site-patterns/{domain}.md` | 单文件流水账 `references/lessons.md` |
| 读取引擎 | `match-site.mjs` 脚本正则匹配 | SKILL.md 规则强制 Phase 0 必读 |
| 经验结构 | 平台特征 / 有效模式 / 已知陷阱 | 单条三段式：现象 → 根因 → 下次规则 |
| 启动暴露 | `check-deps.mjs` 列出已有站点 | Phase 0 第 0 步直接读全文件 |
| 写入触发 | 操作成功后 AI 自主判断 | 同上，且"被用户纠正过 ≥1 次"强制写入 |
| 固化路径 | 留在经验文件 | 能固化的规则同步并入 SKILL.md 正文并标注"已并入" |

**注意**：两边都没有"写入脚本"。写入行为始终由 SKILL.md 的 Prompt 规则驱动 AI 执行。
