# Durable 任务塑形

只在准备长任务、判断 POC、保存 Todo 或确定验收链路时读取本文。本文提供判断方法，不提供必须逐项照抄的固定问卷。

## 一、从终局反推

先回答：

1. 用户最终希望自己的处境发生什么变化？
2. 用户想摆脱哪些等待、盯守或重复决策？
3. 用户需要保留哪些知情权、选择权和节奏控制？
4. 一个真实的人会怎样从输入走到可用结果？
5. 哪些步骤最可能在数小时后造成返工？

把答案整理成一条真实链路：

```text
用户入口 → 关键操作 → 系统反馈 → 异常与恢复 → 最终结果 → 用户验收
```

交付同时包含两部分：

- **结果交付**：网站、PR、部署地址、文件、命令、报告或其他最终产物。
- **过程交付**：用户获得结果所必经的操作是否真实可用。

## 二、先取证，再提问

按当前任务需要检查项目、已有 Todo、可用 Skills、`experience.local.md` 和历史 POC 证据。不要询问能够从现场可靠得到的信息。

动态识别以下最低启动条件：

- 目标与明确产物；
- 用户取得结果的关键操作链路；
- 可观察、可执行的完成标准；
- 关键工具、环境和账号前提；
- 已授权的外部副作用；
- 必须由用户决定的节点；
- 会使后续执行整体失效的能力风险。

这不是固定字段表。简单任务可以用一句话覆盖多项；只在某项不明确会改变方向、权限或验收时继续询问。

## 三、组织问题

- 改变产品方向、交付物或权限边界的问题一次只问一个。
- 相互独立的配置问题可以成组询问。
- 给出有依据的推荐项和影响，不让用户替 AI 处理普通实现细节。
- 用户明确表达的长期偏好可直接沉淀；单次任务选择只保留在当前任务或 Todo。
- 当最低启动条件已清楚时立即停止提问。

## 四、判断 POC

只有同时满足以下条件才建议 POC：

1. 某项关键能力没有可信证据证明可用；
2. 该能力失败会让后续长时间工作失去意义；
3. 现有 Skill、经验或同等环境的成功记录无法消除风险。

环境、凭据、接口或产品前提发生实质变化时，旧 POC 才失效。不要因为进入新会话就重做。

执行前单独向用户说明：

- 要验证的唯一关键假设；
- 为什么它是后续工作的前提；
- 最小真实验证动作；
- 可能花费的时间、额度和外部副作用；
- 成功、失败和跳过分别意味着什么。

得到明确同意后再执行。优先在目标项目和真实链路中做最小验证；只有存在污染、破坏、付款或隔离要求时才建立测试环境。POC 只证明能力可用，不代表用户授权启动 Durable。

验证后保存可复核事实：环境前提、动作、证据、结论和失效条件。可分享规律进入对应 Skill；本机事实进入其 `experience.local.md`。

## 五、确定 Human in the Loop

保留人类真正不可替代的决定：

- 明显不同且难以回退的产品方向；
- 新权限、付款、正式发布、真实消息、删除或生产风险；
- 无法由现有目标推导的主观选择；
- 安全替代路径已经穷尽的真实阻塞。

以下事项不构成人工节点：

- 框架内的普通技术选择；
- 可逆的 UI 或代码修改；
- 测试失败、构建失败和依赖排查；
- 可以通过项目默认值或已有偏好解决的问题；
- 只为了汇报阶段进度。

## 六、保存为 Todo

用户选择稍后执行时，调用 `todo` Skill，通过它的 CLI 保存，禁止直接编辑任务文件。

尚未满足最低启动条件时：

- 状态保存为 `shaping`；
- 写入已经确认的目标、产物、链路、决定和剩余关键问题。

已经满足最低启动条件时：

- 状态保存为 `canDurable`；
- 写入目标、明确产物、完整使用链路、完成标准、工作区、工具与环境、权限边界、POC 结论和 Human in the Loop 条件；
- 按 Todo Skill 要求记录合法的 Durable 判断依据。

保存后返回任务 ID、实际路径和一段可复制到新会话的提示词：

```text
请读取 Todo「<任务 ID 或标题>」中已经确认的任务塑形与 POC 结论。
不要重复询问已确认内容，也不要重复仍然有效的 POC。
现在开始 Durable：持续完成实现、测试、独立评审、修复和真实交付。
只有遇到 Todo 中定义的 Human in the Loop 条件时才暂停。
```

新会话只重新确认已经发生实质变化的范围、环境或外部副作用。

## 七、启动前收口

向用户简短复述：

- 最终交付什么；
- 用户如何获得和验收结果；
- 哪些高成本步骤已经被说明；
- 下一次可能需要用户出现的节点；
- 这是可能持续数小时或整夜的执行。

若用户尚未授权启动，则提供：立即开始 Durable、保存为 Todo、继续调整。只有明确选择立即开始，才进入无人值守执行。

若用户已经在本次请求中明确要求开始，且塑形没有发现新的高成本、权限或不可逆事项，则完成上述披露后直接执行，不重复索要同一授权。发现新事项时，只针对新增成本或边界重新确认。
