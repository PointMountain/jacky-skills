# Durable 最终验收契约

> 本文用于把“用户最终如何回归”前置约定清楚，让 Agent 在用户离线期间持续推进，而不是在中间文档和阶段节点频繁暂停。

## 一、Durable 准备度

一个任务只有同时满足以下条件，才可以标记 `canDurable`：

1. **目标稳定**：成功结果、范围和非目标明确。
2. **产物可回归**：最终交付入口与用户的最短验收动作明确。
3. **可以自主完成**：环境、权限、依赖和输入已具备；普通选择有安全默认值。
4. **可以自行验证**：存在测试、构建、浏览器检查、录屏或结构化检查。
5. **失败可恢复**：有重试、替代方案、checkpoint 或至少能保存进度。

缺少中间设计文档不一定阻塞 Durable；缺少最终产品方向、必要凭据或高风险授权才阻塞。

## 二、最终验收模板

在任务正文中使用：

```markdown
## 最终验收

- 最终产物：{网页 / E2E 视频 / Skill / CLI / 文档 / 其他}
- 回归入口：{URL、绝对文件链接、触发提示词或一条命令}
- 用户动作：
  1. {最短步骤一}
  2. {最短步骤二}
- 自动验证：
  - {测试、构建、浏览器检查或扫描}
- 失败条件：
  - {用户可直接观察到的失败}
```

## 三、按产物类型设计

### 3.1 网页或应用

优先级：

1. 在任务授权范围内完成部署，返回可点击 URL。
2. 不能部署时启动本地服务，返回固定 URL。
3. 服务不能持续运行时，提供一条启动命令和启动成功的验证输出。

回归步骤控制在 3–5 步，覆盖主链路而非全部实现细节。

```markdown
- 最终产物：可交互网页
- 回归入口：https://example.test
- 用户动作：
  1. 打开页面。
  2. 导入样例。
  3. 搜索一个事件并打开原始证据。
- 自动验证：构建通过；主链路浏览器测试通过；无控制台错误。
```

只有 URL/本地入口已经可用时，才可以为最终体验回归进入 `waitingHuman`。

### 3.2 E2E

Agent 应交付：

- 使用的环境与数据；
- 实际点击步骤；
- 自动化结果；
- 完整或关键路径录屏；
- 失败截图、控制台或网络证据；
- 一页式视频报告。

```markdown
- 最终产物：E2E 视频报告
- 回归入口：/absolute/path/e2e-report.md
- 视频：/absolute/path/e2e-run.mp4
- 用户动作：观看视频，确认主流程与视觉结果。
- 自动验证：断言全部通过；控制台错误为 0。
```

中间截图、测试计划和用例文档只是执行证据，不触发等待。

### 3.3 Skill

Skill 的验收物不是 SKILL.md 本身，而是用户能复制执行的提示词：

```markdown
- 最终产物：已安装 Skill
- 回归提示词：
  “使用 <skill-name> 对 <最小输入> 执行 <目标>，返回 <预期结果>。”
- 预期行为：
  1. 正确触发 Skill。
  2. 按约束调用工具。
  3. 生成可验证结果。
- 自动验证：结构审计、契约测试和最小场景测试通过。
```

如果 Skill 已经能通过自动场景完全验收，可以直接 `done`；需要体验语言、交互或路由时，再把上述提示词作为最终人工回归入口。

### 3.4 CLI 或 API

提供一条主链路命令、一个失败路径和机器可读结果：

```markdown
- 回归入口：`tool import fixture.jsonl --json`
- 预期：退出码 0，输出包含 `"ok": true`
- 自动验证：单元测试、集成测试与非法输入测试通过。
```

### 3.5 文档或研究

文档是以下两种角色之一：

1. **中间证据**：保存为 Reference，继续下一阶段，不等待用户。
2. **用户明确要求的最终产物**：完成链接、结构、事实、格式和敏感信息检查后设为 `done`，在最终报告给出可点击链接。

不得要求用户阅读长文后回复“通过”才能继续已经约定的后续实现。

## 四、有效阻塞与无效阻塞

### 有效阻塞

- 必须登录或提供凭据，且当前环境没有。
- 必须执行公开发布、付费或不可逆操作，但此前没有授权。
- 两个产品方向会产生明显不同结果，且没有默认选择。
- 外部服务持续不可用，安全重试和替代路径都已失败。

### 无效阻塞

- 一份文档或决策矩阵刚写完。
- 一个阶段完成，但后续阶段仍在既定范围内。
- 可以用项目默认值解决的技术选择。
- 测试失败但尚未诊断或尝试修复。
- 希望用户“看一下是否满意”，但没有可点击、可运行或可观看的最终入口。

## 五、执行记录模板

```markdown
## 执行记录

### Skills 与工具
- `{名称}`：{用途与结果}

### 关键决策
- {决定}：{证据、约束或权衡}

### 问题与解决
- {问题} → {诊断} → {解决或回退}

### 验证
- {命令/场景}：{结果}

### 提效机会
- {下次可减少的步骤、可并行工作、可复用缓存或更早的失败检测}
```

这份记录服务于任务恢复、审计和流程优化，不要求用户逐段阅读。
