# LLM 知识库 - Karpathy 实践总结

> 来源：Andrej Karpathy 的推文，总结了他使用 LLM 构建个人知识库的实际经验

最近我发现一个非常有用的用法：用 LLM 来构建各种研究主题的个人知识库。这样一来，我最近的 token 消耗中，用于操作代码的比例在减少，而用于操作知识（以 Markdown 和图片形式存储）的比例在增加。最新的 LLM 在这方面表现得相当出色。

## 数据摄入

我将源文档（文章、论文、代码仓库、数据集、图片等）索引到一个 `raw/` 目录，然后用 LLM 增量地"编译"一个 wiki——本质上就是一个目录结构中的 `.md` 文件集合。这个 wiki 包含 `raw/` 中所有数据的摘要、反向链接，然后 LLM 会把数据按概念分类、为每个概念撰写文章、并将它们全部链接起来。

要把网页文章转成 `.md` 文件，我喜欢用 Obsidian Web Clipper 浏览器扩展，然后我还用快捷键把所有相关图片下载到本地，这样我的 LLM 就能方便地引用它们。

## IDE

我用 Obsidian 作为 IDE "前端"，在这里可以查看原始数据、编译后的 wiki，以及衍生出来的可视化内容。需要强调的是，**wiki 的所有数据都由 LLM 编写和维护，我很少直接碰它**。我也尝试了一些 Obsidian 插件，以其他方式渲染和查看数据（比如用 Marp 做幻灯片）。

## 问答

有趣的地方在于，一旦你的 wiki 足够大（比如我的某个研究 wiki 大约有 100 篇文章、约 40 万字），你可以向你的 LLM Agent 提出各种复杂的问题，它会自己去研究、找答案。我原本以为需要搞复杂的 RAG，但 LLM 在自动维护索引文件和所有文档的简要摘要方面做得很好，在这个规模下它能相当轻松地读取所有相关的核心数据。

## 输出

相比在终端里看文本回答，我更喜欢让 LLM 渲染 Markdown 文件，或者幻灯片（Marp 格式），或者 matplotlib 图像，这些我都可以在 Obsidian 里查看。你可以想象根据查询的不同，还有很多其他的可视化输出格式。而且我经常会把输出结果"归档"回 wiki，让它为后续查询提供更丰富的内容。**所以我自己的探索和查询总是会在知识库中"积累起来"。**

## 检查

我对 wiki 做过一些 LLM "健康检查"，比如：查找不一致的数据、用网络搜索补全缺失数据、发现有趣的关联以生成新文章候选，等等，从而增量地清理 wiki 并提升其整体数据完整性。LLM 在建议进一步的问题和研究方向方面非常出色。

## 额外工具

我发现自己在开发额外的工具来处理数据——比如我 vibe-code 了一个简单朴素的搜索引擎来检索 wiki，既可以直接使用（通过 Web UI），但更多时候我想通过 CLI 把它交给 LLM 作为处理大型查询的工具。

## 进一步探索

随着仓库的增长，自然的想法是考虑合成数据生成 + 微调，让 LLM 在权重中"掌握"这些数据，而不仅仅依赖上下文窗口。

## 总结

**原始数据从多个来源收集，然后由 LLM 编译成 `.md` wiki，再由 LLM 通过各种 CLI 工具对其进行问答操作并增量增强 wiki，所有这些都可以在 Obsidian 中查看。你几乎从不需要手动编写或编辑 wiki——那是 LLM 的领域。我认为这里有一个令人惊叹的新产品的空间，而不是一堆拼凑的脚本。**
