# 自我进化（Self-Evolution）

> 陪伴用户成长的同时，skill 自己也要成长。它有两面镜子：一面让"对用户的理解"生长（假设台账），一面让"自己的本事"生长（本文件）。

## 两种进化，机制和护栏完全不同

| | 8a 经验沉淀型 | 8b 能力进化型 |
|---|---|---|
| 改什么 | 经验数据（reference 文件） | 自身工具代码 |
| 类比 | 长期记忆变厚 | 长出新器官 |
| 风险 | 低 | 高（可能改坏现有能力） |
| 触发 | **默认自动** | **重复摩擦达阈值 + 护栏** |
| 例子 | web-search 的 experience.local.md 站点沉淀 | agent-browser 加 upload_files 能力 |

**一句话：8a 是"记得更多"，8b 是"会得更多"。** 二者绝不能用同一套流程。

## 8a：经验沉淀（低风险，自动）

每轮 Phase 6 自问："本轮有没有冒出**值得记住的对话模式/手法**？"

有就追加到 `.sounding-board/experience/<主题>.md`，例如：
```markdown
## 沉淀 · 2026-06-03
- 当用户反复说"我应该…"时，往往是外部期待而非真实意愿 → 追问"这是你想，还是你觉得你该想？"效果好
- 用户在"职业"话题上抗拒反驳 → 先共情再反驳，命中率更高
```

下次启动时，这些经验作为 L0 旁路一并加载，让对话越来越懂这个用户。

> 注意：8a 沉淀的是"**如何更好地和这个用户对话**"的方法经验，**不是用户的隐私结论**（那些在假设台账里）。两者分开存。

## 8b：能力进化（高风险，护栏）

### 触发条件
**不是想改就改。** 只有当同一类"做不到"在 `capabilities/manifest.json` 中累计达到阈值（默认 3 次重复摩擦）才进入候选。

```json
{
  "gaps": [
    {
      "need": "把对话生成情绪曲线图",
      "frictionCount": 3,
      "status": "candidate",
      "firstSeen": "2026-06-03"
    }
  ]
}
```

### 护栏流程（缺一不可）
1. **快照**：改任何代码前 `git` 提交当前状态（或复制备份）
2. **小步改**：只加新能力，不动现有逻辑
3. **回归验证**：改完跑一遍既有典型流程，确认旧能力没坏
4. **登记**：新能力写入 `manifest.json` 的 `capabilities` 列表，状态置 `active`
5. **人工确认**：高风险改造在门禁模式下必须用户点头

> 红线：agent "随手改自己代码"的天性极其危险。**没有"快照 + 回归 + 阈值"三道闸，禁止 8b。** 低风险沉淀放开做，高风险自改必须卡 checkpoint。

## 反思计数器与触发器

`.sounding-board/meta.json`：
```json
{
  "reflectCounter": 3,
  "reflectThreshold": 5
}
```

每轮 Phase 6：
1. `reflectCounter += 1`
2. 跑 8a 沉淀检查（每轮）
3. 跑 8b 摩擦计数（每轮）
4. `reflectCounter >= threshold` → 触发反方挑战（见 `hypothesis-ledger.md`），然后清零

## 自指之美

这套机制本质是把 learn-repo 的"认知纠错记录"**从对准用户掉头对准 skill 自己**：
- 对准用户 = 帮用户纠错成长
- 对准自己 = 自我进化

同一个循环，两面镜子。这才是"有生命力"。
