# 假设台账（Hypothesis Ledger）

> 核心理念：**关于"你"的每一条认知，都是假设，不是结论。** 它会被证据支持、被反证削弱、被后来的对话推翻。"没有永恒正确"在这里落地成数据结构。

## 为什么是"假设"而不是"结论"

自我认知没有标准答案，今天的判断明天可能被推翻。如果系统把判断当结论固化，就会制造**叙事固化**——一旦贴了标签（"你童年缺爱所以回避亲密"），用户和 AI 都会用它解释一切，形成自证预言。

把每条认知建模为**带状态、带置信度、带证据与反证**的假设，才能让"被推翻"成为系统的一等公民。

## 单条假设 schema

每条假设一个文件：`hypotheses/H-<id>-<slug>.md`

```markdown
# H-017：我回避亲密关系，是因为害怕被评判

- 状态：🟡 活跃   （🟡活跃 / 🔵已修订 / ⚫已推翻）
- 置信度：中      （低 / 中 / 高）
- 提出于：2026-06-03
- 最近复核：2026-06-03

## 支持证据
- 2026-06-03 用户："约会前总想找借口取消"
- 2026-06-10 用户："很在乎别人怎么看我"

## 反证
- 2026-06-20 用户："工作汇报里我完全不怕被评判" ← 出现裂缝，置信度下调

## 修订记录
- 2026-06-20 → 拆分出 H-023：回避可能只发生在"亲密关系"而非"所有社交场合"
```

## 状态机

```
        新证据支持              反证累积 / 出现裂缝
活跃 ──────────────► 活跃    活跃 ──────────────────► 已修订（拆分/收窄）
                                          │
                              决定性反证   ▼
                            活跃 ────────────► 已推翻（保留留痕，不删除）
```

- **已修订**：不是错，是变得更精确（收窄范围 / 拆分）。原文件状态改 🔵，新增子假设。
- **已推翻**：⚫ 标记，**保留不删**——推翻的过程本身是宝贵的认知轨迹。

## 置信度调节规则

| 事件 | 动作 |
|---|---|
| 新增独立支持证据 | 置信度 +1 档（封顶"高"） |
| 出现一个反证 | 置信度 −1 档 |
| 反方挑战未能驳倒它 | 维持，并记录"经受住挑战" |
| 反方挑战驳倒它 | 降为"低"或转「已修订/已推翻」 |

## 反方挑战机制（防叙事固化）

`.sounding-board/meta.json` 维护一个 `reflectCounter`。每完成一轮对话 +1，到达阈值（默认 5）时，Phase 6 强制触发：

1. 选出当前**置信度最高**的活跃假设
2. AI **切换为反方人格**，全力攻击它：找反例、找另一种解释、质疑证据是否被过度解读
3. 把挑战结论写入该假设的"反证 / 经受住挑战"记录，并相应调节置信度
4. 计数器清零

> 这一步是硬性的。一个长期没被挑战过、置信度却很高的假设，是叙事固化的危险信号。

## 与 self-model 的关系

- 每条假设的**当前状态摘要**冒泡到 `self-model.md` 的"活跃假设清单"
- self-model 只放摘要（一行），完整证据链留在各假设文件 —— 对应渐进式加载的 L0 vs L2
