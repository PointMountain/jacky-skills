# 扩展协议（Extension Protocol）

> 本文是 ob-collect 的扩展范式详解。SKILL.md 主体只保留「可扩展点」+「6 条硬约束」，沉淀机制和职能边界细节在这里。
>
> 与 web-search 同范式：**能力按需累加 + 经验沉淀 + 约束在范式之内**。
> - web-search 沉淀「怎么找到内容」（站点路由 / 工具降级链 / 本机扩展 CLI）
> - ob-collect 沉淀「哪些内容值得保留 + 怎么归档」（raw 子目录 / 主题分类 / 提取约束）

## 沉淀机制（约束在范式之内）

发现新的采集模式后，写入 `${OBSIDIAN_REPO}/.kb/collect-experience.md`（不存在就创建）。

### 写入规则

| 触发条件 | 写入位置 | 内容格式 |
|---------|---------|---------|
| 某类内容重复出现 ≥ 3 次，值得新建子目录 | 「新增子目录」表 | `\| 子目录 \| 适用域名 \| frontmatter 模板 \| 日期 \|` |
| 某类内容的 frontmatter 需要新字段 | 「字段扩展」表 | `\| type \| 字段名 \| 用途 \| 日期 \|` |
| OpenCLI 返回结构有解析陷阱 | 「解析陷阱」表 | `\| 平台 \| 陷阱 \| 解决方式 \| 日期 \|` |
| 某主题反复被命中但未匹配现有目录 | 「新增主题」表 | `\| 主题 \| 目录 \| 关键词 \| 日期 \|` |

### 不写

- 一次性临时归档（≤ 2 次出现的内容模式）
- 未经验证的猜测
- 可在现有目录消化的内容
- 与 web-search 路由相关的经验（应该写到 web-search 的 experience.local.md）

### collect-experience.md 模板

首次创建时使用以下骨架：

```markdown
# Obsidian 采集经验沉淀

> 由 LLM 自动维护。只写经过验证的事实，不写未确认的猜测。
> 与 SKILL.md 的「可扩展点」配套：固化后回填到 SKILL.md 对应表格。

## 新增子目录

| 子目录 | 适用域名 | frontmatter 模板 | 日期 |
|--------|---------|----------------|------|

## 新增主题

| 主题 | 目录 | 关键词 | 日期 |
|------|------|-------|------|

## 字段扩展

| type | 字段名 | 用途 | 日期 |
|------|-------|------|------|

## 解析陷阱

| 平台 | 陷阱 | 解决方式 | 日期 |
|------|------|---------|------|
```

### 固化回流

当一条经验**累计验证 ≥ 3 次稳定**后，应**反向更新到 SKILL.md 的对应表格**，并从 collect-experience.md 删除该条：

- 子目录稳定 → 写入 SKILL.md「平台 → raw 子目录映射」表
- 主题稳定 → 写入 SKILL.md「主题关键词映射」表
- 字段稳定 → 写入 references/frontmatter-schema.md
- 解析陷阱稳定 → 写入 SKILL.md「异常处理」表

> 经验沉淀是**临时缓冲层**，最终目标是把规律固化回主体；防止经验文件膨胀。

## 职能边界（与 web-search 的分工）

| 决策 | 谁负责 | 落地位置 |
|------|--------|---------|
| URL 用什么工具拿 | web-search | web-search SKILL.md Layer 1-4 |
| 本机有没有相关 CLI | web-search | web-search「本机扩展 CLI」机制 |
| 通用搜索用哪个引擎 | web-search | web-search Layer 2 降级链 |
| 放 raw/ 哪个子目录 | **本 skill** | SKILL.md「平台 → raw 子目录映射」表 |
| 该类型留哪些 frontmatter | **本 skill** | references/frontmatter-schema.md |
| 视频要不要下载 / 字幕怎么处理 | **本 skill** | SKILL.md 视频范式硬约束 + ASR 回退流程 |
| 编译到 wiki/ 哪个主题 | **本 skill** | SKILL.md「主题关键词映射」表 |
| 文章关联到哪些已有概念 | **本 skill** | 写入后验证流程 |

## 何时跨边界

少数场景两个 skill 的边界会模糊，处理原则：

| 场景 | 处理 |
|------|------|
| 新平台的字幕命令不存在 | 走 web-search Layer 1 兜底（`opencli list \| grep`），失败再写到本 skill 的「解析陷阱」表 |
| 已知 URL 但 web-search 多次失败 | 本 skill 不重试，回到上层让用户决定（如确认登录态、交由 Ego Lite）|
| 用户说「采集这个话题」 | 先调 web-search Layer 2 搜索 → 列出候选 URL → 用户选定 → 本 skill 采集 |
| 内容包含视频又包含文字（如带视频的微信文章）| 文字走通用流程，视频部分按视频范式（只存字幕）|
