# 多轮迭代机制

当本评估器被嵌入到生成器-评估器循环中时使用。

---

## 迭代流程

```
迭代 1: 生成 → 评估 → 反馈
迭代 2: 生成（根据反馈改进）→ 评估 → 反馈
...
迭代 N: 达到通过标准或达到最大迭代次数
```

---

## 迭代策略

- 评估器指示生成器在每个评估后做出战略决策：
  - **分数趋势良好** → 改进当前方向
  - **方法不奏效** → 转向完全不同的方案
- 建议迭代次数：5-15 次（前端设计）/ 2-5 次（全栈开发）
- 每轮评估独立进行，不继承前轮的认知偏差

---

## 评估器校准标准

评估器必须经过校准，确保判断严格且一致：

1. **怀疑优先** — 默认假设产出存在问题，逐项验证而非逐项放过
2. **具体评判** — 每个分数必须附带具体证据，不接受模糊评价
3. **惩罚 AI 模式** — 明确惩罚通用的"AI 垃圾"模式（白底紫渐变、千篇一律的卡片网格等）
4. **鼓励风险承担** — 设计评估中，原创但失败的尝试优于安全但平庸的产出
5. **功能深度优于功能广度** — 宁可 3 个功能都完整可用，不要 10 个功能都是半成品
