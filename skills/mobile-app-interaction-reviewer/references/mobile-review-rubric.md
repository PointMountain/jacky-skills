# Mobile App 交互评审量规

## 一、核心任务与信息预算

- 首屏先表达当前上下文、核心内容、主操作和退出/返回路径；辅助说明按需展开，不与主操作争夺固定空间。
- 固定 Header、Tab bar、输入区、播放器和悬浮按钮占用空间后，核心内容仍有足够可操作区域。
- 小屏不直接压缩桌面多栏、长说明或大选择器。优先改为分步页、详情页、Bottom sheet、全屏 Dialog 或按需展开。
- 截断只用于可恢复的信息；路径、模型名、错误原因等完整值应有可发现的点击查看方式。

## 二、可发现性与触控

- 关键动作和状态不能依赖 hover、Tooltip、右键或鼠标精准定位。
- 纯图标入口应有熟悉语义、邻近上下文或可见标签；长按提示不能修复首次发现性。
- 触控目标按平台惯例接近 iOS 44pt、Android 48dp，并保留防误触间距；不要把 CSS px、pt 和 dp 混作同一单位。
- 同一区域的滚动、横滑、边缘返回和拖拽不互相抢手势；关键能力有非手势替代入口。
- 禁用、按下、加载、成功和失败状态有即时可见反馈；重要反馈不只依赖触觉。

## 三、键盘、输入与安全区

- 软键盘打开后，焦点字段、当前输入、主提交动作和必要错误仍可见；页面能滚动到被聚焦字段。
- 键盘收起、返回键、外点和提交的行为一致，不造成内容跳跃、重复提交或草稿丢失。
- 顶部状态栏、刘海/灵动岛、底部 Home indicator、Android 导航栏和横屏边缘均不遮挡可操作内容。
- 输入法候选栏、语音输入、粘贴长文本和多行输入不会把发送区或主要动作挤出屏幕。

## 四、弹层与选择器

| 容器 | 移动端适用任务 |
|---|---|
| Menu / Popover | 少量轻量命令；锚点附近空间充足且不会贴边裁切 |
| Bottom sheet | 短到中等选择、局部设置、可单手完成的上下文任务 |
| Dialog | 简短确认或必须打断当前任务的决定 |
| Fullscreen / Drill-in page | 搜索、长列表、多步骤配置、预览或需要键盘的复杂任务 |

- 弹层考虑动态视口、键盘和安全区；长内容内部滚动，首项、末项和确认/取消均可达。
- Bottom sheet 不堆入桌面式标题、长说明、多栏和多级悬浮层；内容复杂时升级为全屏或独立页面。
- 系统返回只关闭最上层可关闭内容；关闭后上下文、焦点和滚动位置符合预期。
- 背景不滚动穿透；拖拽关闭、外点关闭和显式关闭按钮遵循任务风险。

## 五、文字、密度与无障碍

- 正文、辅助说明和占位文本在真实设备上可读；颜色和透明度不把必要信息降成装饰。
- 系统字体放大后，标签可换行或布局重排，不遮挡、截断主操作或制造横向滚动。
- 屏幕阅读器名称、顺序和状态与视觉任务顺序一致；动态反馈可被辅助技术感知。
- 不为了“显得简洁”移除必要标签；空间不足时优先减少同时出现的次要内容。

## 六、设备与状态矩阵

至少覆盖与改动相关的组合，而不是机械跑全矩阵：

- 小型手机宽度、典型手机宽度；Mobile Web 可用 360×800 与 390×844 作为起点。
- 竖屏；产品支持横屏时补横屏和低高度场景。
- 软键盘关闭/打开；默认字体/放大字体。
- 空、1 项、典型数量、长列表、超长名称、加载、失败、离线、权限不足。
- 首次打开、重复打开、系统返回、快速连点、切后台再回来。

## 七、问题与证据契约

| ID | 严重度 | 平台/设备 | 页面/入口 | 复现步骤 | 实际结果 | Mobile 预期 | 证据 | 回归标准 |
|---|---|---|---|---|---|---|---|---|

- **P0**：阻断核心任务、数据损坏、无法退出或高风险误操作。
- **P1**：主操作不可达，被键盘/安全区/弹层遮挡，或关键状态不可理解。
- **P2**：任务可完成，但明显损害单手效率、发现性、可访问性或跨状态稳定性。
- **P3**：文案、对齐、轻微视觉或非关键一致性问题。

只有可复现、能说明用户影响且有可观察 Mobile 预期时，才确认为问题。截图边缘裁切、未知滚动位置或模拟器差异不足以单独证明阻断。
