# Mobile 回归验收模式

按既定问题、验收点或 Case 复跑，不扩展为无边界探索。

## 一、冻结可比条件

| Case ID | 原问题 | 平台/设备 | 方向/字体/键盘 | 固定步骤 | 通过标准 | 补充边界 |
|---|---|---|---|---|---|---|

优先保持原平台、设备宽度、系统版本、方向、字体/显示缩放、键盘状态和数据前置条件。若只能换设备或用 Mobile Web 代理，披露差异并把无法等价证明的项记为证据不足。

## 二、逐 Case 复跑

1. 恢复前置状态并记录构建版本。
2. 捕获动作前画面与键盘/系统栏/滚动状态。
3. 严格走原触控和系统返回路径，不改用更容易成功的替代入口。
4. 捕获动作后画面、状态、焦点、键盘、返回与必要日志。
5. 对照通过标准，并补测与修复直接相关的小屏、长内容、字体放大、键盘和重复打开边界。
6. 清理本 Case 临时状态后再进入下一 Case。

可见 UI Case 每项独立交付前后证据，保持相同设备条件、方向、字体/显示缩放和键盘状态。跨平台截图只能补充上下文，不能组成同一 Case 的前后对比。

## 三、判定与输出

逐 Case 只使用“已修复 / 仍失败 / 证据不足 / 阻断”，路径内新失败另记新增回归。只有所有计划 Case 均已修复，才判定本轮通过。返回总 verdict、逐 Case 预期与实际、证据、设备差异、未覆盖项和建议下一步；不修改代码、创建 PR、发布或合并。
