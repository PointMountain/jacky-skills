# Mobile 交互走查模式

用于可运行原生 App 或窄屏 Mobile Web 的只读交互验收。先冻结设备条件和核心任务，再以触控、软键盘和系统导航复现真实路径。

## 一、建立环境与状态矩阵

登记构建版本、平台/系统、设备或视口、方向、字体/显示缩放、登录与数据前置条件。建立：

| 核心任务 | 页面/状态 | 设备条件 | 可达性 | 结果 | 未覆盖原因 |
|---|---|---|---|---|---|

至少让核心任务进入一个代表性的已填充或活跃状态；只看空壳和首页不能声称移动端走查完成。

## 二、建立触控入口清单

从可见标签、图标、列表项、Tab、弹层、手势提示和系统返回路径收集安全入口：

| 页面/区域 | 入口 | 发现依据 | 手势/动作 | 安全级别 | 前置状态 | 结果 |
|---|---|---|---|---|---|---|

关键能力如果只能靠未说明的长按、边缘滑动或 hover 才能发现，记录为缺口。涉及保存、删除、授权、上传、发送或支付时停在安全门前。

## 三、逐 Case 执行

每个 Case：

1. 动作前记录画面、滚动、焦点、键盘与系统栏状态。
2. 用真实触控语义执行点击、滚动、拖拽或系统返回；Mobile Web 鼠标点击只能作为近似，不能证明手势和命中区。
3. 等待可观察稳定状态，不只依赖固定延时。
4. 动作后记录新增/消失内容、状态反馈、遮挡、滚动、焦点、键盘和返回行为。
5. 对输入流程至少覆盖键盘打开、提交/返回、收起键盘和长文本；对弹层覆盖首尾内容、关闭和背景滚动。
6. 页面或状态变化后重新发现入口，不复用失效定位。

## 四、边界复测

按改动风险选择小型手机、典型手机、横屏、放大字体、低高度和切后台恢复。原生特性必须在原生环境证明；窄屏 Web 结果不能替代安全区、系统返回、触觉和原生键盘证据。

## 五、输出

只有核心状态、全部计划安全入口和相关设备边界都有结果，未覆盖项有原因时，才能判定完成。输出总 verdict、设备条件、状态/入口覆盖、逐 Case 前后证据、P0–P3 问题、证据不足项和最短回归路径。
