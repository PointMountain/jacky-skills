# Web E2E 经验写回

经验的目标是减少下一次探索，不是保存完整执行历史。

## 最小判断

写入前确认：

- 下次可能再次遇到；
- 根因已经通过源码、日志或复跑确认；
- 解法已经真实验证；
- 能指出适用项目或 Case；
- 不含密钥、令牌或登录态内容。

条件不满足时，把内容留在当次报告，不要升级为长期经验。

## 推荐表达

优先使用短表格：

```markdown
| 现象 | 已确认原因 | 已验证解法 |
|---|---|---|
| 页面 200 但测试仍失败 | JS bundle 尚未完成 | 等 bundle 可下载后再启动 Playwright |
```

必要时补充：

- 最近验证日期和代码版本；
- 失败信号或关键日志；
- 不适用的边界；
- 已确认无效的旧解法。

## 维护旧经验

- 新结论完全替代旧结论：直接修正旧条目。
- 只在部分版本失效：标记适用范围，保留仍有效部分。
- 经验已固化到自动化代码：将长排障过程压缩为测试或脚本入口。
- 多次使用仍没有帮助：删除，避免噪声。

不要只在文件末尾不断追加“最新结论”，让相互矛盾的记录同时存在。
