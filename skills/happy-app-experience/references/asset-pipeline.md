# 视觉资产前置管线

**最近验证：** 2026-07-12

从 Happy/Paws 实践提炼：独立 App 的视觉资产应当**前置**，不是最后补图。

## 资产前置，而非事后补图

**决策：** 在堆功能之前先把视觉语言与核心资产定下来——App icon、adaptive icon、splash、
首屏/场景图、空状态图、营销/Release 图。先写清 prompt 与视觉约束（风格、配色、留白、情绪），
再生成；prompt 文件与最终产物都入库、可追溯。资产缺位会让「可用首屏」退化成占位页。

**适用边界：** 对内容型/生活方式 App 尤其关键（沉浸感来自图不是卡片）；纯工具型可克制，但
icon/splash/空态仍是最低集合。资产是产品的一部分，不是可选装饰。

**在本机怎么生成：** 用 `gpt-image-2` skill。它对 Claude Code 特判为**委托 `codex exec` 出图**
（Claude Code 无内置图像工具），因此在 Claude 会话里也能一条链路出图，无需额外网关。典型形态：

```
codex exec --skip-git-repo-check -s danger-full-access \
  "生成图片并保存到 /绝对路径/输出.png：<最终 prompt>。完成后输出图片绝对路径"
```

`gpt-image-2` 提供 18 大类、80+ 模板与 prompt 工程约束，优先走它而不是手写裸命令。

**迁移到其他 App：** 保留「先定视觉语言与 prompt 约束 → 再批量生成 → 入库可追溯」的顺序；
出图工具可替换，但资产前置这条不变。
