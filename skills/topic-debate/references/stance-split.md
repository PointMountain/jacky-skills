# 立场拆分指南（步骤 0，编排器中立工作）

> 这是**编排器**的工作，不是辩论。把一句话辩题拆成 2~4 个互斥、有意义、可被反驳的立场。拆完才知道要起几个辩手。

## 原则

1. **每个立场必须能拿出明确、可被攻击的主张**——不能是「都有道理」「看个人」这种和稀泥（除非它本身是一个有具体边界条件的「折中派」立场）。
2. **立场之间互斥**：不能两方说的其实是一回事。
3. **数量由辩题决定，不硬凑**：
   - 二元对立题 → **2 方**（最常见）。
   - 多选项 / 程度题 / 开放题 → **3~4 方**，可包含一个有清晰适用边界的「折中 / 看情况」派。
4. 拆不出 **≥2 个**有意义对立立场 → 判定「这不是辩题」，停止并建议用户改用普通问答。

## 示例

| 辩题 | 拆出的立场 |
|------|-----------|
| 相亲好还是自由恋爱好 | ① 相亲更优　② 自由恋爱更优 |
| 远程办公 vs 坐班 | ① 全远程更高效　② 坐班更高效 |
| 大学要不要读热门专业 | ① 追热门专业　② 选兴趣/天赋　③ 看家庭与就业市场的折中派 |
| AI 会不会取代程序员 | ① 会大规模取代　② 不会、只会改变工作形态　③ 取代初级、放大高级（分层派） |

## 产出

一张映射表（编排器自己持有）：

```
立场1 → 辩手乙(Codex)   "相亲更优"
立场2 → 辩手甲(Claude)  "自由恋爱更优"
立场3 → 辩手丙(Claude)  "看情况的折中派"   # 如有
```

**注意**：映射表里的「Codex/Claude」只供编排器分配用，**绝不写进任何发给辩手或裁判的提示**。发给辩手的只有「你是辩手X，死守『<立场>』」。
