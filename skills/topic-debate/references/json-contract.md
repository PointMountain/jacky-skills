# JSON 契约（topic-debate 唯一事实源）

> 所有提示词与编排逻辑都引用本文件定义的结构，不要在别处重复定义。

## 单条论点 argument

```json
{
  "id": "A1",
  "point": "论点一句话（你方主张的一个支点）",
  "reasoning": "论证：为什么这个论点成立",
  "evidence": "论据 / 例子 / 数据（可选，没有可省略或填空字符串）"
}
```

## 单条反驳 rebuttal（仅交叉轮出现）

```json
{
  "target": "辩手乙 A2",
  "type": "反驳|质疑|让步",
  "content": "针对对方该条论点的反驳内容（反驳必须给理由；让步要说明让到哪一步）"
}
```

- `target`：你针对的是哪位辩手的哪条论点（用「辩手X + 论点 id」定位）。
- `type`：`反驳`（指出对方论点错误/无效）/ `质疑`（要求对方补充论据）/ `让步`（承认对方某点成立，但限定范围）。

## 每轮信封 envelope

```json
{
  "stance": "你死守的立场（首轮确立，之后每轮原样重复，不得改变）",
  "arguments": [ /* argument[] —— 本轮新增或强化的论点 */ ],
  "rebuttals": [ /* rebuttal[] —— 首轮为空数组，交叉轮针对他方 */ ],
  "no_new_points": false
}
```

- `stance`：本方立场，全程不变（辩论不要求妥协）。
- `arguments`：本轮提出的论点。首轮是开篇立论；后续轮只填**新增 / 强化**的论点（炒冷饭不算新论点）。
- `rebuttals`：本轮对他方的反驳。首轮 `[]`。
- `no_new_points`：**本轮你是否已无新论点、也无新反驳可提**（布尔）。这是停机信号——当所有辩手本轮都为 `true`，辩论自然终止。若你只是重复旧论点凑数，应诚实填 `true`。

## 输出纪律

**只输出一个 JSON 对象**，不要任何解释文字、不要寒暄、不要在 JSON 之外写 markdown。若需代码围栏，只用一个 ```json ``` 块包裹整个 envelope。
