# 全站交互 E2E 走查模式

> 用于 URL 或可运行构建的探索式、只读交互验收。核心是建立可点击入口清单，逐项执行，并对比每次动作前后的画面、页面状态、Console 与 Network 增量。

## 进入条件与边界

- 全站任务：覆盖可达页面及其全部安全交互入口。
- 指定流程任务：只覆盖该用户路径，以及必要的打开、关闭、返回、异常和边界状态。
- 已有固定问题 ID 或验收 Case 时，应改用 [regression-acceptance.md](regression-acceptance.md)，避免把回归变成无边界探索。

开始前读取 [desktop-review-rubric.md](desktop-review-rubric.md)，并委派 `dev-tools:browser-control` 处理 provider、登录态、安全门、账本和浏览器证据。需要自动化脚本时再委派 `web-e2e`。

## 一、建立环境与基线

至少登记：

1. 非敏感页面标识、构建版本、登录态和数据前置条件。
2. 视口与缩放；默认覆盖 `1280×720`、`1440×900`、`1920×1080`，边界桌面补 `1024×768`。
3. 初始截图、URL/标题或等价页面标识、可见页面状态。
4. 初始 Console 与 Network 基线；既有 warning/error 与本轮新增问题分开记录。

## 二、建立动态交互清单

从导航、DOM、可访问性树和可见控件收集所有可点击或可键盘激活的入口，包括链接、按钮、标签页、菜单、选择器、浮层入口、折叠控件和媒体操作。

| 页面/区域 | 入口 | 定位证据 | 安全级别 | 前置状态 | 结果 | 后续入口 |
|---|---|---|---|---|---|---|

要求：

1. 为入口分配稳定 ID，标记未测、通过、失败、阻断或需确认。
2. DOM 明显变化、页面跳转、浮层打开或列表异步刷新后，重新获取入口，不复用失效定位。
3. 新出现的安全入口追加到清单；已经验证的同状态入口不要无意义重复点击。
4. 涉及写操作的入口停在安全门前，未获确认不得为了“点完所有元素”而执行。

## 三、逐入口执行前后对比

每次安全交互都执行以下闭环：

### 动作前

1. 截取当前画面，记录可见状态、滚动位置、焦点和相关控件包围盒。
2. 记录当前页面标识、关键 DOM/可访问性状态。
3. 为 Console 与 Network 建立本次动作的增量起点。
4. 写明预期变化：打开浮层、切换内容、导航、下载或保持原状态；没有明确规格时标记为待确认，不伪造产品预期。

### 执行动作

1. 鼠标点击或等价键盘激活。
2. 等待页面进入稳定状态；异步请求不能只以固定延时判断完成。
3. 对 Menu、Dialog、Listbox、Combobox 等继续检查 Tab、Enter/Space、Esc、外点关闭和焦点恢复。

### 动作后

1. 再次截图，并与动作前画面对比新增、消失、移动、遮挡、溢出和反馈状态。
2. 对比页面标识、关键 DOM/可访问性状态、焦点和滚动锁。
3. 只读取本次动作新增的 Console 与 Network；记录新增 error、失败 XHR/Fetch、异常重试和长时间 pending。
4. 判断实际变化是否符合预期。截图相似度、DOM 变化、页面跳转或工具成功文本都不能单独证明通过。

新增 Console error 或失败 XHR/Fetch 默认使相关 Case 失败；若能证明与本次动作无关，必须保留基线和因果证据。已有 warning 不归因给本次动作。

## 四、边界与状态

关键入口至少检查：

1. 首次打开、重复打开、关闭、返回及关闭后焦点恢复。
2. 长内容、空内容、加载、错误、权限不足和快速连点。
3. 页面滚动、浮层内部滚动、低高度视口、窗口缩小及 100% 缩放。
4. 浮层与触发器、固定栏和视口边界的关系；背景是否滚动穿透。
5. 危险动作仅验证安全门、文案和可达性，不越权提交。

## 五、完成与输出

只有所有已列安全入口均有结果，动态入口已重新扫描，未覆盖项有原因时，才能声称走查完成。

输出顺序：

1. 结论：通过 / 不通过 / 证据不足。
2. 覆盖统计：页面数、入口总数、已测、失败、阻断、需确认和未覆盖数。
3. 入口覆盖表，以及每个失败项的动作前后截图或状态证据。
4. 页面、Console、Network 三类增量结果。
5. P0/P1 阻断项和完整问题表。
6. 可复现 E2E Case：前置条件、步骤、预期、实际与证据。

不得因“主要页面看过”或“自动化脚本跑完”声称全站完成；未点完的入口必须明确列出。
