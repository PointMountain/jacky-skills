# PC Web 交互评审 Prompt

## 截图快速评审

```text
使用 $pc-web-interaction-reviewer 的截图评审模式检查这张 PC 页面截图。先盘点最大内容、最大空白、最孤立入口，以及左侧、核心、右侧等持久或候选区域的用途、内容、占宽和可见收起/恢复入口；没有分隔线时也不要跳过单侧大块闲置空间。只报告当前画面有证据支持的布局、比例与视觉问题，按影响排序；每项说明位置、画面事实、用户影响、PC 端预期和置信度。最后给出最值得先改的 3 项，并把交互未知项写成验证问题、动作与判定标准。单帧边缘裁切不能直接证明固定栏遮挡。不要点击页面，不要把静态画面当成 E2E 证据，也不要修改代码。
```

## 指定页面评审

```text
使用 $pc-web-interaction-reviewer 评审这个 PC 页面：{URL 或页面路径}。重点检查信息层级、空间利用、操作入口、弹窗/下拉框、状态反馈、滚动、键盘与焦点。输出可复现问题和修复优先级，不要直接改代码。
```

## 全站交互走查

```text
使用 $pc-web-interaction-reviewer 的全站交互 E2E 走查模式检查 {产品或 URL}。覆盖 1280×720、1440×900 和 1920×1080；先建立页面类型 × 数据/任务状态矩阵，确保核心任务进入代表性的已填充、详情或活跃状态，再建立动态入口清单并逐页操作全部安全入口。每次动作前后分别截图并比较页面状态、Console 与 Network 增量，DOM 变化后重新发现入口。检查打开、关闭、Esc、外点、长内容、空状态、错误状态和视口边界。输出状态覆盖、入口统计、未覆盖原因、P0–P3 问题、前后证据及 E2E Case；缺少核心动态状态或未点完入口时不得声称完成。
```

## Agent 委派

```text
你是独立 PC Web 交互评审 Agent。使用 $pc-web-interaction-reviewer 只读评审 {截图、录屏、URL 或构建}，范围限定为 {页面或流程}。不要接受生产者自评作为结论，不要修改产物。返回按优先级排序的问题清单；每项包含复现位置、实际结果、用户影响、PC 端预期、证据等级和待验证项。
```

## 修复后回归

```text
使用 $pc-web-interaction-reviewer 的回归验收模式复测以下 PC 交互问题：{问题清单、ID 或 Case}。先冻结既定范围，按原复现路径和通过标准逐 Case 复跑，只补测与修复直接相关的窗口缩放、长内容、Esc、焦点恢复和重复打开。逐项输出已修复、仍失败、证据不足、阻断或路径内新增回归；不要扩展为无边界全站探索，没有证据时不要判定通过。若任务包含 PR，检查实际 PR 正文是否声明可见 Case 数并为每个可见 Case 直接嵌入唯一的修复前后截图组；本地报告、聊天图片、总览图和合并后失效的分支链接不算完成。数量不一致、图片未渲染或任一 Case 缺图时不得允许合并。
```
