# PC Web 全站交互评审量表

> 用于全站走查和回归验收。先建立实际页面与交互清单，再逐项使用本量表。

## 一、页面级

- 主内容在桌面断点下有合理最大宽度或明确的宽屏布局策略。
- 固定侧栏、顶栏、右栏和底部输入区不会互相侵占。
- 页面无横向溢出；缩小窗口后内容不会被固定区域永久遮住。
- 页面滚动位置、返回行为和刷新后的状态符合用户预期。
- 空、加载、错误、离线、权限不足状态有明确下一步。

## 二、交互入口

- 可点击元素有悬停、按下、焦点和禁用反馈。
- 图标按钮有可访问名称和 Tooltip；命中区适合鼠标，不依赖像素级点击。
- 同一动作不会在页面不同位置使用互相矛盾的控件类型。
- 危险操作有明确文案、二次确认或可撤销机制。
- 点击后有即时反馈，异步操作不会重复提交。

## 三、浮层和选择器

- 容器类型与任务复杂度匹配。
- 打开后焦点进入，关闭后焦点回到触发器。
- Esc、外部点击和关闭按钮的行为一致且可预测。
- 浮层不会被顶栏、触发器、侧栏、输入区或浏览器边缘遮挡。
- 长内容受限于视口，内部滚动，关键操作可达。
- 嵌套浮层有清晰层级，关闭内层不会误关外层。
- 重新打开不会残留旧滚动位置或错误状态，除非产品明确需要记忆。

## 四、桌面信息密度

- 正文通常保持易读行长，复杂信息可分栏而非无限拉宽。
- 菜单、列表、表单没有沿用不必要的移动端超大行高和字号。
- 辅助说明弱于主标签，但仍满足可读性。
- 长英文、路径、地址和标签在窄空间内有截断、换行或查看完整值的方式。
- 搜索、筛选、列表和主操作的位置符合桌面扫描顺序。

## 五、滚动与视口矩阵

每个关键浮层至少在以下尺寸实测：

| 视口 | 目的 |
|---|---|
| 1024×768 | 边界桌面和低高度 |
| 1280×720 | 常见低高度笔记本 |
| 1440×900 | 默认桌面基准 |
| 1920×1080 | 宽屏与最大宽度控制 |

检查：

- `document.scrollWidth <= window.innerWidth`
- 浮层 `left/top >= 安全边距`
- 浮层 `right/bottom <= 视口 - 安全边距`
- 固定区域与主操作包围盒不相交
- 内部滚动能到达第一项和最后一项
- 触控板滚动不会穿透到背景

## 六、键盘矩阵

| 操作 | 预期 |
|---|---|
| Tab / Shift+Tab | 顺序符合视觉与任务逻辑 |
| Enter / Space | 激活当前控件 |
| Arrow keys | 在 menu/listbox/combobox 内移动 |
| Home / End | 长选择列表按语义跳转 |
| Escape | 仅关闭最上层可关闭浮层 |
| 关闭后 | 焦点返回原触发器 |

## 七、状态矩阵

对列表、画廊、模型选择、文件选择等数据型交互覆盖：

- 0 项、1 项、典型数量、超长列表。
- 超长名称、重复名称、缺少描述。
- 加载中、请求失败、部分资源失败。
- 搜索无结果、清空搜索、切换筛选。
- 快速重复打开关闭、快速连点、请求未完成时离开。

## 八、问题是否成立

满足以下三项才可定为确认问题：

1. 有明确复现步骤或稳定截图证据。
2. 能说明对完成任务、理解状态、操作效率或可访问性的影响。
3. 有可观察的 PC 端预期行为。

只有审美偏好、无法复现或缺少影响说明时，标记为建议或待验证，不冒充缺陷。
