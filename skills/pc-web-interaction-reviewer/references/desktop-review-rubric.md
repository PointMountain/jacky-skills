# PC Web 全站交互评审量表

> 用于全站走查和回归验收。先建立实际页面与交互清单，再逐项使用本量表。

## 一、页面级

- 主内容在桌面断点下有合理最大宽度或明确的宽屏布局策略。
- 固定侧栏、顶栏、右栏和底部输入区不会互相侵占。
- 页面无横向溢出；缩小窗口后内容不会被固定区域永久遮住。
- 页面滚动位置、返回行为和刷新后的状态符合用户预期。
- 空、加载、错误、离线、权限不足状态有明确下一步。

## 二、多栏工作区与全局模式

- 对左侧辅助区、核心工作区、右侧辅助区和检查器逐栏记录：当前用途、可见内容或状态、占用空间、收起入口、收起后的空间回收、恢复入口和状态记忆。
- 栏位不以边框或背景色为成立条件；单侧大块闲置空间、贴边控件或明显不对称的内容宽度也要登记为候选辅助区，再通过运行态确认其状态模型。
- 每个持久辅助区应有当前任务价值、明确的有意空状态及下一步，或在无内容时收起；不以无说明的空白表面长期占位。
- 左右辅助区分别检查，不用“一并可折叠”替代证据。收起后主工作区应真正回收空间，恢复入口应明显且不依赖记住隐藏手势。
- 有移动端、窄屏实现、产品说明或用户确认可对照时，核对核心能力是否保留。容器和密度可以改变；快捷命令、导航或任务入口若在 PC 无说明消失，应记录为能力一致性问题或规格待确认。
- 禅模式、沉浸模式、专注模式等全局模式不能只依赖难以理解的孤立图标。入口应让新用户理解用途，启用后应表达当前状态，并始终有明确退出路径。
- 可访问名称只能满足辅助技术语义，不能替代视觉发现性；Tooltip 应同时支持悬停和键盘焦点。截图只能确认可见语义和状态，实际 Tooltip、键盘与切换行为需运行态验证。

## 三、交互入口

- 可点击元素有悬停、按下、焦点和禁用反馈。
- 图标按钮有可访问名称和 Tooltip；命中区适合鼠标，不依赖像素级点击。
- 同一动作不会在页面不同位置使用互相矛盾的控件类型。
- 危险操作有明确文案、二次确认或可撤销机制。
- 点击后有即时反馈，异步操作不会重复提交。

## 四、浮层和选择器

- 容器类型与任务复杂度匹配。
- 打开后焦点进入，关闭后焦点回到触发器。
- Esc、外部点击和关闭按钮的行为一致且可预测。
- 浮层不会被顶栏、触发器、侧栏、输入区或浏览器边缘遮挡。
- 长内容受限于视口，内部滚动，关键操作可达。
- 嵌套浮层有清晰层级，关闭内层不会误关外层。
- 重新打开不会残留旧滚动位置或错误状态，除非产品明确需要记忆。

先按任务选择容器，再评审样式：

| 容器 | 适用任务 |
|---|---|
| Menu | 少量、即时、轻量命令，锚定触发器 |
| Listbox / Combobox | 单选或多选；长列表需要受限高度、内部滚动和键盘导航 |
| Popover | 与触发器强相关的简短设置或预览；空间不足时翻转、偏移或收缩 |
| Dialog | 需要集中注意，包含搜索、筛选、预览或确认的复杂任务 |
| Side panel | 需要与主内容并行查看并持续存在的辅助工作区 |
| Drawer / Bottom sheet | 优先用于窄屏或手势场景，不因复用窄屏组件而直接用于桌面 |
| Fullscreen | 真正沉浸式或大画布任务，且必须提供明显退出路径 |

复杂画廊、长选择器或多步骤配置在桌面端通常需要有边界的 Dialog，而不是占满工作区的底部抽屉。以下尺寸只能作为实现起点，不是固定规范：

```css
.desktop-dialog {
  width: min(960px, calc(100vw - 48px));
  max-height: calc(100dvh - 48px);
  overflow: hidden;
}

.desktop-dialog__body {
  overflow: auto;
  overscroll-behavior: contain;
}
```

## 五、桌面信息密度

- 正文通常保持易读行长，复杂信息可分栏而非无限拉宽。
- 菜单、列表、表单没有沿用不必要的移动端超大行高和字号。
- 辅助说明弱于主标签，但仍满足可读性。
- 长英文、路径、地址和标签在窄空间内有截断、换行或查看完整值的方式。
- 搜索、筛选、列表和主操作的位置符合桌面扫描顺序。

## 六、滚动与视口矩阵

每个关键浮层至少在以下尺寸实测：

| 视口 | 目的 |
|---|---|
| 1024×768 | 边界桌面和低高度 |
| 1280×720 | 常见低高度笔记本 |
| 1440×900 | 默认桌面基准 |
| 1920×1080 | 宽屏与最大宽度控制 |

检查：

- `document.scrollWidth <= window.innerWidth`
- 浮层 `left/top >= 安全边距`
- 浮层 `right/bottom <= 视口 - 安全边距`
- 固定区域与主操作包围盒不相交
- 内部滚动能到达第一项和最后一项
- 触控板滚动不会穿透到背景

## 七、键盘矩阵

| 操作 | 预期 |
|---|---|
| Tab / Shift+Tab | 顺序符合视觉与任务逻辑 |
| Enter / Space | 激活当前控件 |
| Arrow keys | 在 menu/listbox/combobox 内移动 |
| Home / End | 长选择列表按语义跳转 |
| Escape | 仅关闭最上层可关闭浮层 |
| 关闭后 | 焦点返回原触发器 |

## 八、状态矩阵

对列表、画廊、模型选择、文件选择等数据型交互覆盖：

- 0 项、1 项、典型数量、超长列表。
- 超长名称、重复名称、缺少描述。
- 加载中、请求失败、部分资源失败。
- 搜索无结果、清空搜索、切换筛选。
- 快速重复打开关闭、快速连点、请求未完成时离开。

## 九、问题是否成立

满足以下三项才可定为确认问题：

1. 有明确复现步骤或稳定截图证据。
2. 能说明对完成任务、理解状态、操作效率或可访问性的影响。
3. 有可观察的 PC 端预期行为。

只有审美偏好、无法复现或缺少影响说明时，标记为建议或待验证，不冒充缺陷。

静态截图边缘的部分可见内容可能来自任意滚动位置或截图裁切。没有稳定重叠证据时，不把它升级为固定栏遮挡或核心任务阻断。

## 十、问题与证据契约

每个问题独立记录：

| ID | 严重度 | 页面/入口 | 复现步骤 | 实际结果 | PC 预期 | 证据 | E2E 验收 |
|---|---|---|---|---|---|---|---|

严重度：

- **P0**：阻断核心任务、数据损坏或无法退出。
- **P1**：主要操作不可达、严重遮挡或溢出、键盘被困。
- **P2**：任务可完成，但明显损害桌面效率、一致性或可访问性。
- **P3**：文案、细节或轻微视觉瑕疵。

证据类型使用“截图”“录屏”“DOM/尺寸测量”“可访问性树”“Console/Network”或“用户确认”。用户确认与画面推断分开记录；没有运行态证据时不要断言点击、键盘或请求行为。

## 十一、可观察 E2E 契约

验收断言面向用户可观察结果，不绑定内部 class 名。常见契约包括：

- 浮层包围盒完整位于视口安全区，且不与触发器或固定控件相交。
- 长列表容器可滚动，首项与末项均可到达和选择。
- Esc 关闭最上层浮层，焦点回到原触发器。
- 桌面视口使用合适的有边界容器，窄屏才切换 Drawer 或 Sheet。
- 页面与背景没有横向溢出、滚动穿透或残留滚动锁。
- 方图、横图和竖图的默认预览不撑破内容列或侵占大部分视口。
- 多图不退化为逐张超大纵向堆叠；关闭大图预览后焦点回到原缩略图。
- 操作产生预期可见状态，且没有本次动作新增的 Console error 或失败 XHR/Fetch。
