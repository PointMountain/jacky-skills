# slugify-cli 设计文档

> 一个把剪贴板里的文本转成 URL slug 的命令行小工具。

## 目标

用户复制一段标题文本后，运行 slugify，工具读取剪贴板内容，转成小写连字符 slug（如 "My First Post!" → my-first-post），并把结果写回剪贴板。

## 功能

1. 读取系统剪贴板的纯文本。
2. 转换规则（按顺序应用，确保输出可重复）：
   1. Unicode NFKC 归一化后转小写。
   2. 非 ASCII 字符（含 CJK、重音字母等）一律移除；保留集合为 `[a-z0-9]`。
   3. 空白字符（空格、Tab、换行）转为单个连字符 `-`。
   4. 下划线 `_` 视为分隔符，转为连字符 `-`。
   5. 移除 `[a-z0-9-]` 之外的所有特殊字符。
   6. 连续连字符合并为一个 `-`。
   7. 去除首尾连字符。
3. 把 slug 写回剪贴板，并在终端打印结果（仅 slug 一行，输出到 stdout）。

> 字符规则需完全闭合：相同输入在任何平台必须产生相同的 slug。非 ASCII 输入（如纯中文标题）经移除后可能得到空串，按下方边界处理。

## 边界与错误处理

| 场景 | 行为 | 退出码 |
|------|------|--------|
| 正常转换出非空 slug | 写回剪贴板 + stdout 打印 slug | 0 |
| 剪贴板为空 | 不写回，stderr 提示「剪贴板为空」 | 1 |
| 剪贴板内容非文本（如图片） | 不写回，stderr 提示「剪贴板无文本内容」 | 1 |
| 清洗后 slug 为空（如纯符号/纯 CJK） | **不写回**（避免破坏剪贴板），stderr 提示「无法生成有效 slug」 | 1 |
| 剪贴板不可访问（headless/无 DISPLAY） | 不写回，stderr 提示具体错误 | 2 |

> 核心安全约束：**任何情况下都不得把空串写回剪贴板**，以免破坏用户已有内容。

## CLI 契约

- `slugify`：无参数，执行剪贴板转换主流程。
- `slugify --help` / `-h`：打印用法说明，退出码 0。
- `slugify --version` / `-v`：打印版本号，退出码 0。
- stdout：成功时仅输出 slug 本身（一行，无多余装饰），便于管道消费。
- stderr：所有错误与提示信息走 stderr。
- 退出码：成功 0；可预期错误（空剪贴板/非文本/空 slug）1；环境不可用（剪贴板不可访问）2。

## 技术选型

- Node.js + clipboardy 读写剪贴板。
- 纯本地、零网络依赖：转换逻辑全部内置，不加载任何外部代码。

> 插件机制（自定义转换插件 / `~/.slugify/plugins.json` / 远程 URL 加载）在 MVP 中移除：远程加载外部代码等同于任意代码执行（RCE）安全风险，且会破坏「输出始终为合法 slug」的确定性保证。如未来确有扩展需求，另行设计带沙箱与签名校验的安全方案。

## 使用

```
slugify
# 剪贴板 "Hello World" → 写回并打印 hello-world
```

## 完成标准

工具满足以下可机器验证的条件即视为完成：

1. **退出码**：正常转换返回 0；可预期错误返回 1；剪贴板不可访问返回 2。
2. **剪贴板值**：成功时剪贴板内容被替换为合法 slug（仅含 `[a-z0-9-]`、无首尾连字符、无连续连字符）；任何失败路径下剪贴板内容保持不变。
3. **stdout**：成功时 stdout 精确等于 slug + 换行；失败时 stdout 为空，错误信息走 stderr。

示例验收：剪贴板置为 `"Hello World"`，运行 `slugify`，断言退出码为 0、剪贴板与 stdout 均为 `hello-world`。

## 采纳/驳回理由表

| 共识点 | 裁决 | 理由 |
|--------|------|------|
| 1. slug 字符规则未闭合（歧义,major） | 采纳 | 不定义非 ASCII/CJK/首尾连字符/空白处理就无法保证输出可重复，验收无依据，必须闭合规则。 |
| 2. 边界遗漏（major） | 采纳 | 空剪贴板/非文本/headless/空 slug 是真实高频路径，写回空串会破坏用户剪贴板，必须显式定义行为。 |
| 3. 插件机制应整体删除（过度设计 major + blocker） | 采纳 | 远程加载代码构成 RCE，且与「输出恒为合法 slug」自相矛盾，MVP 无接口无验收，应删除。 |
| 4. 完成标准与核心目标矛盾（内部矛盾,major） | 采纳 | 原标准不可机器验证，改为退出码+剪贴板值+stdout 三条件后才能客观验收，消除矛盾。 |
| 5. CLI 契约缺失（需求覆盖 minor） | 采纳 | 退出码/stdout 纯 slug/stderr 分流/--help/--version 是 CLI 工具基本契约，补全成本低、收益明确。 |
